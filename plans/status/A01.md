- [x] The benchmark login flow (GET /session/new, POST /session -> 302 + session_token) works with
  CSRF on
  - `SessionsControllerTests.The_benchmark_login_signs_in_with_the_pages_token` does what the
    load generator does: GET /session/new, reads `authenticity_token` from the form and posts it
    back with the `_campfire_session` cookie the page set; the answer is 302 to
    `http://campfire.test/` with a `session_token` cookie.
  - `SessionsControllerTests.The_vectors_cover_the_benchmark_login` pins the reference's side of
    it: the sign-in page (200, with the token), the sign-in POST (302 to the root plus
    `session_token`), the same POST without a token (422) and the eleventh attempt in three
    minutes from one address (429).
- [x] Ported controller tests pass with CSRF enabled
  - **The oracle.** `tests/Campfire.Web.Tests/Controllers/Sessions/Vectors/generate.rb` runs in the
    reference app (`parity/bin/reference runner --storage … --time 2026-03-02T16:00:00Z --freeze`,
    native runtime, Ruby 3.4.10 built from the `v3_4_10` tag) on a copy of D02's parity seed and
    sends 49 requests in order straight to `Rails.application`, with CSRF protection on (the
    session cookie plus the form's `authenticity_token`, as the sign-in form posts it). For each it
    records the response (status, `content-type`, `location`, `vary`, `cache-control`,
    `set-cookie`, `x-frame-options`, body), the Action Cable broadcasts and every changed row of
    `accounts`, `users`, `rooms`, `memberships`, `sessions` and `push_subscriptions`. Midway it
    empties the database, so the last cases run against a new install. Output:
    `Vectors/sessions.json`.
  - The cases cover reference/test/controllers/sessions_controller_test.rb,
    first_runs_controller_test.rb and welcome_controller_test.rb and more: the sign-in page
    (signed out, signed in, with `?email_address=`, JSON 406, an unsupported browser's
    `sessions/incompatible_browser` page); sign in (right password, wrong password, unknown
    address, deactivated, banned user, blank password, no params, back to the remembered URL, no
    CSRF token 422, a banned IP 429); the root (signed out, first room, the `last_room` cookie's
    room, no rooms page, no rooms as JSON 500); `/first_run` and its create once set up (redirect);
    `/session` show and `/first_run/edit` (404, AbstractController::ActionNotFound); sign out with

    administrator, "All Talk" and its membership, a session, `user[role]` ignored), a repeat, and

  - `SessionsControllerTests.Each_request_answers_and_changes_what_the_reference_did` replays
    every request in order through W01's router, W02's pipeline and these controllers on the same

    placeholders; membership timestamps, which SQLite stamps (`insert_all`) and the reference's
    frozen clock stops; and `Vary: Accept-Encoding` from Rack::Deflater.
  - `bin/check` is green.

## Notes for dependents

- `SessionsPages.RenderActionAsync` / `RenderTemplateAsync` (Controllers/SessionsPages.cs) render a
  page in the application layout without requiring a `Current.user` or an account: the implicit
  render (406 for a request that takes no HTML) and an explicit `render` (500 then).
- `ApplicationController.IncompatibleBrowserPage` is implemented, so `allow_browser` renders
  `sessions/incompatible_browser` for every controller.
- `SessionsController.CreateRateLimit` is `rate_limit to: 10, within: 3.minutes` over an in-process
  fixed window per remote IP (Redis' `INCRBY` with `EXPIRE … NX`), kept per `WebApp`.
- bcrypt is `Campfire.RailsCompat.Crypto.SecurePassword` (BCrypt.Net-Next, checked against the
  Rails vectors): `Digest` for `password=`, `Authenticate` for `authenticate_password`. It lives in
  C01's directory and adds the package to F02's files; both tasks are done, and A02/A07 need it
  for password changes and joins.
- `accounts/_help_contact` is rendered from `Views/sessions/_help_contact.html.erb.cs`
  (`View.AccountsHelpContact`), since `Views/accounts/` is A02's; A02 can move it.

## Known gaps

- Sign out doesn't send `user.reset_remote_connections`' disconnect broadcast because the server
  doesn't set `WebApp.ResetRemoteConnections` (W02's hook for the realtime lane). The test leaves
  it out for that case.
- Rails' cookie jar sends sign out's `session_token` twice (re-signed while authenticating, then
  deleted); C02's jar sends only the deletion. Browsers keep the last, so the result is the same.
- A first-run avatar is attached (blob and attachment rows, the file kept on commit), but
  Active Storage's `AnalyzeJob` isn't enqueued: `Campfire.Data.Events` has no such job yet.
- `email_address` given as an array or hash (Rails' `find_by` would query with it) answers 500.
