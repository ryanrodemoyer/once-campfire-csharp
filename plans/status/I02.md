## Notes for dependents

- Namespace `Campfire.Jobs.WebPush`. To wire it up in the server (P lane):
  ```csharp
  var guard = PrivateNetworkGuard.System;
  var client = new WebPushClient(RestrictedHttpHandlers.WebPush(guard), guard, VapidIdentification.FromEnvironment(), TimeProvider.System);
  var pool = new WebPushPool(client, WebPushPool.DestroySubscription(database, log), log);
  new MessagePusher(database, pool, session => new DatabaseAttachables(session, keys, clock.GetUtcNow()), clock).RegisterWith(runner);
  // at shutdown, after the job runner: await pool.ShutdownAsync();
  ```
  `VapidIdentification.PublicKey` is the layout's `vapid-public-key`.
- A07 (test notification): build
  `new WebPushNotification("Campfire Test", <random body>, <user_push_subscriptions_url>, badge, subscription.Endpoint, subscription.P256dhKey, subscription.AuthKey)`
  and `await notification.DeliverAsync(client)` inline. Errors propagate, as they do in Rails. To get
  a "local push endpoint", pass a `WebPushClient` over a handler whose `Dialer` goes to a loopback
  TLS server. `tests/Campfire.Jobs.Tests/WebPush/PushServiceServer.cs` is one.
  `PushEndpoint.ValidationErrorsAsync(guard, endpoint)` returns `errors[:endpoint]` for
  `Push::Subscription` validation.
- Removing subscriptions follows Rails exactly: `WebPush::Pool#deliver` rescues
  `WebPush::ExpiredSubscription` (410) and `OpenSSL::OpenSSLError`. The OpenSSL errors are a p256dh
  that isn't a P-256 point, a VAPID key OpenSSL refuses, and a failed TLS session
  (`OpenSSL::SSL::SSLError`). A 404 raises `WebPush::InvalidSubscription`, which is a sibling of
  `ExpiredSubscription`, not a subclass. It is logged ("Error in WebPush::Pool.deliver: …") and the
  subscription stays. The card says "404/410 subscription removal", but the gem source (errors.rb,
  request.rb) is the oracle. `MessagePusherTests.Keeps_subscriptions_the_push_service_does_not_know`
  pins this.
- Missing VAPID keys behave as `VapidKey.from_keys(nil, nil)` does: each request signs with a newly
  generated pair, so push services refuse it.
- A p256dh key is read the way OpenSSL reads it. Leading zero bytes are dropped (`BN.new(bytes, 2)`),
  and compressed and hybrid points are accepted. The key info then carries the key bytes exactly as
  given, as the gem does.

## Known gaps

- Net::HTTP's open and read timeouts (60 s each, left at their defaults) are approximated by the
  handler's 60 s connect timeout plus a 120 s deadline on the whole exchange.
- Request headers differ from Net::HTTP only in `Accept-Encoding`, where SocketsHttpHandler sends
  `gzip, deflate`. Push services ignore it, and these requests never take part in replay or
  benchmarks. If README "Known differences" should list it, that needs the README's owner.
- `tests/Campfire.Jobs.Tests/RestrictedHttp/RestrictedHttpHandlersTests.cs`: the loopback server's
  accept loop now also catches the `InvalidOperationException` that a stop between two accepts throws
  ("Not listening"). That test flaked once with it under the extra parallel load from these tests.
