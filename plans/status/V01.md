## What landed

- `parity/bin/reference`: the Rust port's runner, with the same interface (`build`, `up`, `down`,
  `logs`, `ps`, `exec`, `runner`, plus `path`). `build` makes `campfire-reference:app` from
  `reference/Dockerfile` and the `campfire-reference` parity image from `parity/docker/`. Every
  instance runs `RAILS_ENV=production` with the fixed keys in `parity/.env.reference`. Changes from
  the Rust script:
  - the native runtime finds Ruby at `reference/.ruby-version` through rbenv;
  - it fetches libfaketime and Redis with `git clone` (some networks block GitHub tarballs) and
    uses the host's `redis-server` when there is one;
  - native builds live in `parity/.seed/.native`, which `.gitignore` already covers;
  - `down` under Docker refuses to delete a native instance's directory. In the Rust script that
    orphaned the native processes.
- `parity/docker/`: the parity image (libfaketime without FAKE_PTHREAD, sqlite3, a one-worker
  resque-pool, the single-worker Action Cable initializer, and test fixtures for the seed builder).
  The only changes from the Rust port are in comments.
- `compose.parity.yml`: a `seed` step copies `parity/.seed/$PARITY_SEED` over fresh volumes for
  both apps. Then `reference` and `candidate` start with the same env file, CPU cap, `FAKETIME`
  and `/rails/storage/{db,files}` layout. Both serve on container port 3000, mapped to host ports
  3100 and 3200.
- `reference-tools/`: V03 left these scripts for V01 to adapt. `regenerate` runs every vector
  generator through `parity/bin/reference` into `tmp/vectors/`. `compare.rb` then checks each
  output against `vectors/`. `run.sh`, `storage/run.sh` and `richtext/run.sh` now go through the
  runner, and the opengraph/webhook oracles read and write `vectors/<name>/`.
- `plans/tasks.yaml`: added `parity/.env.reference` to V01's `owns`. The reference-tools scripts
  and the compose file read the env file at that path, as in the Rust port.

## Acceptance evidence

- [x] parity/bin/reference build && up serves /up and a logged-in room page.
  - This sandbox can't build the Docker image: the egress policy blocks deb.debian.org, so
    `reference/Dockerfile`'s `apt-get` fails. The evidence below uses the native runtime, which runs
    the same pinned app (Ruby 3.4.10, the reference's `Gemfile.lock`, precompiled assets, Thruster,
    Puma, Resque, Redis).
  - `PARITY_RUNTIME=native parity/bin/reference build` succeeded: bundle install, assets:precompile
    and libfaketime.
  - A one-user seed was built with `parity/bin/reference exec --storage tmp/seeds/smoke -- bash -c
    'bin/rails db:prepare && bin/rails runner tmp/smoke_seed.rb'` (`FirstRun.create!`).
  - `parity/bin/reference up --seed smoke --port 3100` came up in 7.7 s.
  - `curl /up` returned 200 (Rails' green health page).
  - `GET /session/new`, then `POST /session` without `authenticity_token`, returned **422**: CSRF is
    on.
  - With the form's token, `POST /session` returned 302 to `/` and set `session_token` and
    `_campfire_session`.
  - Following the redirect landed on `GET /rooms/1` with 200, `<title>All Talk</title>` and the
    message composer (`id="composer"`).
  - `parity/bin/reference runner --port 3100 tmp/smoke_config.rb` printed `env: "production",
    perform_caching: true, cache_store: "ActiveSupport::Cache::RedisCacheStore", show_exceptions:
    :all, consider_all_requests_local: false, forgery_protection: true`.
- [x] Candidate slot accepts any image exposing port 3000 with the same env contract.
  - `compose.parity.yml` was run under a local `dockerd`. Both slots used a stand-in image: a
    20-line Ruby server on :3000 that reports its env and `/rails/storage`.
  - Settings: `REFERENCE_IMAGE=standin CANDIDATE_IMAGE=standin PARITY_SEED_DIR=tmp/seeds
    PARITY_SEED=smoke PARITY_FAKETIME="@2026-03-02 16:00:00"`.
  - After `docker compose -f compose.parity.yml up -d`, `seed` exited 0 and `reference` and
    `candidate` were running.
  - Ports 3100 and 3200 each answered `/up`. Each slot's `/env` reported `uid 1000`,
    `RAILS_ENV=production`, the parity `SECRET_KEY_BASE`, `DISABLE_SSL=true`, the `FAKETIME` spec,
    and its own copy of `production.sqlite3` owned by uid 1000.
  - With `PARITY_SEED=nope`, the seed step fails with `seed isn't built: parity/bin/seed build
    nope` and neither app starts.
  - Without `CANDIDATE_IMAGE`, `docker compose config` refuses with `set CANDIDATE_IMAGE to the
    image under test`.
- [x] The imported vector generators (reference-tools/) run against this reference and reproduce
  vectors/.
  - Run: `PARITY_RUNTIME=native PARITY_SEED_DIR=$PWD/tmp/seeds reference-tools/regenerate`. The
    default seed was built in `tmp/seeds` from the Rust port's `parity/seeds/build.rb default`; V02
    owns the real one. The run exits 0.
  - **Byte-identical**: `campfire_routes.json`, `campfire_user_agents.json`, `ruby_core.json`,
    `rqrcode.json`, `richtext/expected.json`, `opengraph/expected.json`, and 10 of the 11
    `storage/` media files.
  - **varies** (`rails_compat.json`, `campfire_sessions.json`, `webhook/expected.json`): every
    other field is equal. The fields that differ change on every run by design:
    - AES-GCM IVs;
    - masked CSRF tokens and session ids;
    - bcrypt salts;
    - permanent-cookie expiries computed from the wall clock;
    - the oracle server's ephemeral port.

    `compare.rb` lists each such JSON path.
  - **media** (native runtime only): `storage.json` differs only in the libvips/ffmpeg version
    strings and the video poster's checksum, plus `has_secure_token` blob keys, and
    `storage/alpha-centuri-preview_image.jpg` differs. Host ffmpeg is 6.1.1 and the image's is
    7.1.5. Under Docker, compare.rb counts these as DIFFERS.
  - **Checking the checker**: changing `now` in a regenerated `rails_compat.json`, or a blob
    filename in `storage.json`, turns them into DIFFERS and the exit status into 1.
  - The committed rich-text corpus was generated with no mutation cases, so `regenerate` passes
    `RICHTEXT_MUTATION_CASES=0`.
- `bin/check` passes.

## Notes for dependents

- **V02** (seed): `parity/bin/reference exec --storage DIR` and `runner --storage DIR` work as the
  Rust `parity/bin/seed` expects. `reference-rust/parity/seeds/build.rb default` built a 4.9 MB
  default seed through them unchanged. `regenerate sessions` and `compose.parity.yml` read
  `parity/.seed/<name>` and honour `PARITY_SEED_DIR`.
- **Candidate contract** (P01 and the replay tasks): serve on :3000, read `parity/.env.reference`
  plus `FAKETIME`, and keep data in `/rails/storage/db` and `/rails/storage/files` as uid 1000.
  `parity/bin/reference up` exposes Thruster on port 80. The compose file exposes the app port
  3000 for both apps, so the comparison and benchmarks bypass Thruster on both sides.
- When the Docker daemon is reachable, `PARITY_RUNTIME` defaults to `docker`. Pass
  `PARITY_RUNTIME=native` to keep using native instances.
- Native output is not canonical for media bytes. Use Docker (CI or a workstation) for anything
  byte-golden from libvips or ffmpeg.

## Known gaps

- The Docker image build (`parity/bin/reference build` under Docker) wasn't exercised here because
  deb.debian.org is unreachable from this sandbox. The Dockerfiles are the Rust port's, unchanged
  apart from comments. The first Docker run of `reference-tools/regenerate` should confirm
  `storage.json` and the poster come out `same` or `varies`.
- `reference-tools/views/`, `http_shape/`, `db/` and `rails_compat_verify_rust.rb` still write to
  the Rust layout (`crates/...`). They don't produce anything in `vectors/`. The tasks that port
  those checks (R01 view goldens, Q-lane state) adapt them.
