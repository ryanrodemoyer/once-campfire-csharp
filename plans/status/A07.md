## Notes for dependents

- `UsersPushSubscriptionsController` serves index, create and destroy. `new`, `show`, `edit` and
  `update` are `ActionNotFound` (404), matching Rails. The test notification is
  `UsersPushSubscriptionsTestNotificationsController`. Both ignore `params[:user_id]` and use
  `Current.user`.
- Create finds an existing row by only the permitted keys that were sent, validates the stored
  endpoint before touching it, and validates a new endpoint before inserting. Destroy casts the
  id the way Active Record casts an integer and redirects even when nothing was deleted.
- `WebApp.WebPush` is the app's `WebPush.payload_send` client. P01 can set it and dispose it.
  When it is unset, a test notification opens one client from `VAPID_PUBLIC_KEY` and
  `VAPID_PRIVATE_KEY` and disposes it after that delivery. Subscription checks use
  `WebApp.PushGuard` (the client's guard, or `PrivateNetworkGuard.System`).
- No stand-in template mentioned A07. Q02 can treat these routes as implemented.

## Known gaps

- The pages were not opened in a browser. The HTML was compared to the reference response, and
  the test notification was checked against a local push endpoint.
- A non-2xx push response propagates (500). The pool's "destroy this subscription" path is I02's,
  and this action does not call it.
