## Notes for dependents

- **CLI** (`src/Campfire.Server/Cli/Commands.cs`): `campfire [server|db:prepare|backup]`.
  `server` is the default, and leading options go to Kestrel (`campfire --urls http://…`).
  - `server` is `bin/start-app`. It resolves the secret, loads the asset bundle, runs
    `db:prepare` (D01's `SqliteDatabase.Open`, with `RAILS_MAX_THREADS` readers, 10 by default),
    then serves.
  - Exit codes: 0 on success. 1 for a missing or invalid setting or pending migrations; the
    message goes to stderr as `campfire <command>: …`. 64 for usage errors.
- **Backup (P04)**: implement the hook `static partial void Backup(ServerSettings settings,
  TextWriter error, ref int? exitCode)` of `Campfire.Server.Cli.Commands` in your own file under
  `src/Campfire.Server/Backup/` (`namespace Campfire.Server.Cli; public static partial class
  Commands { … }`), and set `exitCode`. Write to `settings.BackupsPath`/`<db file name>`.
  Without the hook, `campfire backup` prints `not implemented yet (task P04)` and exits 1. The
  image already has `/hooks/pre-backup` (`campfire backup`) and the reference's `post-restore`.
- **Env contract** (`ServerSettings`, read once at startup):
  - `RAILS_ENV` (default `production`), `SECRET_KEY_BASE`, `SECRET_KEY_BASE_DUMMY`.
  - `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`: raw values, null when unset.
  - `DISABLE_SSL` (blank means SSL is on), `TLS_DOMAIN` (P03's).
  - `CAMPFIRE_STORAGE_PATH` (default `storage`), from which come `DatabasePath`
    (`storage/db/<env>.sqlite3`, or `CAMPFIRE_DATABASE_PATH`), `FilesPath` (`storage/files`,
    Active Storage's `local` root) and `BackupsPath` (`storage/backups`).
  - `CAMPFIRE_ASSETS_PATH`: the `bin/build-assets` output, default `artifacts/assets`. The image
    sets `/app/assets`.
  - `PORT` (default 3000), `RAILS_MAX_THREADS`, `APP_VERSION`/`GIT_REVISION` (`AppVersion` as
    version.rb computes it).
  - Relative paths resolve against the working directory (`Rails.root`, `/rails` in the image).
    These names follow the Go port's.
- **Pipeline** (`ServerCommand.Build`): AssumeSSL+SSL when `Ssl` is on, then F04's `StaticFiles`,
  then W01's `Router` with `public/<status>.html` error pages from the asset bundle. That is
  Rails' middleware order. W02 adds its controller pipeline inside the router's handlers, so
  nothing here needs to change for it. If a task needs another Rack-level middleware, ask on #26.
- **SSL**: with `assume_ssl` and `force_ssl` both on (the reference ties both to `DISABLE_SSL`),
  every request is `ssl?`. `request.Scheme` is `https`, and `X-Forwarded-Proto: https` and
  `X-Forwarded-Port: 443` are set, as AssumeSSL sets them. W02 should build `UrlBase` from these.
  Responses get HSTS, and every `Set-Cookie` gets `; secure` unless it already has it. C02's
  `ToSetCookieHeaders(ssl, …)` can be passed `request.IsHttps`.
- **DI**: the app registers `ServerSettings`, the `SqliteDatabase`, the `AssetBundle` and a
  `KeyGenerator` over the resolved `secret_key_base` (`Rails.application.key_generator`). Handlers
  in `Campfire.Web` can't see `ServerSettings`. If they need a setting, ask for it on #26, and it
  will be registered as a type from a lower assembly.
- **Kestrel**: no `Server` header, no request body limit (Puma has neither), and the listener is
  `http://0.0.0.0:$PORT` unless `--urls`/`ASPNETCORE_URLS` is given.
- **Image**: a .NET SDK build stage (published self-contained for `TARGETARCH`, so amd64 and arm64
  both work) and a `debian:trixie-slim` runtime, like the reference's `ruby:3.4-slim`. Microsoft
  publishes no Debian image for .NET 10. P02 adds the media libraries to the runtime stage.
  - `/app` holds the app and `/app/assets`, and `/usr/local/bin/campfire` links to it.
  - `/rails/bin/boot` runs `campfire server`. `/rails/storage/{db,files,backups}` and
    `/rails/tmp` belong to uid 1000.
  - `RAILS_ENV=production`, plus the reference's `HTTP_*_TIMEOUT` defaults (Thruster's, for P03).
    `APP_VERSION`/`GIT_REVISION` come from build args.
  - `EXPOSE 3000`. P03 puts Thruster on 80/443 in front of it and should change `EXPOSE` to the
    reference's `80 443`.

## Known gaps

- **The full `docker build` wasn't run here.** The session's proxy can't be used from build
  containers, so the build stage's NuGet restore and the runtime stage's `apt-get install
  ca-certificates` couldn't reach the network. Everything after them was run as described above:
  the same `dotnet publish` and asset build on the host, then the runtime stage. B01/B04 (or P03)
  should run the first real `docker build` on a networked machine. No CI job builds the image yet.
- `/up` and the login page answer 501 until A08 and A01 bind their handlers.
- Thruster (80/443, TLS via `TLS_DOMAIN`, the `HTTP_*` timeouts) is P03. Backup is P04. The
  media toolchain is P02.
- Logging is ASP.NET Core's console logger, not Rails' log lines. Nothing compares logs.
