  byte-identically to Erubi. Two layers, both against ActionView's own Erubi (erubi 1.13.1 and

    `Translation_changes_only_the_code_inside_tags` asserts each translation's markup is the Ruby

- [x] Zero reflection at render time; Native AOT compatible. Generated code is plain calls on

## Notes for dependents

- How to translate a view and declare its render method: `src/Campfire.Templates/README.md`.
  In short: `[ErbTemplate("rooms/show.html.erb.cs")] static partial void Show(HtmlWriter w, ...)`
  with the template in `AdditionalFiles` and removed from `Compile`. Campfire.Web needs those two
  items (its csproj is F02's/the Web owner's; the generator reference already exists).
- Runtime types (`Campfire.Templates`): `HtmlWriter` over `IBufferWriter<byte>` (`WriteLiteral`,
  `Append` = Rails `append=`, `AppendRaw` = `safe_expr_append=`, `Capture` = `OutputBuffer#capture`),
  `SafeString` (html_safe string), `IHtml` (content that writes itself; block helpers and
  partials). `Append` has overloads for `string`, `SafeString`, `IHtml`, `int`, `long`, `bool`
  only, so a value whose Ruby `to_s` differs from .NET (floats, times) fails to compile instead of
  rendering differently.
- Block helpers (W03): `<%= Helper(args, () => { %>…<% }) %>`. Return an `IHtml` that writes its
  markup around the block, or use `writer.Capture(body)` when the helper needs the block's output;
  Rails' `capture`/`content_for` rules (blank buffer falls back to the block value) belong in the
  helper, not the writer.
- Generator diagnostics: CFT001 template not found, CFT002 ambiguous path, CFT003 invalid method,
  CFT004 unclosed block expression. Template code errors carry `#line` mappings to the template.
- Regenerate goldens after a reference bump with `ruby tests/Campfire.Templates.Generator.Tests/Erubi/generate.rb`
  (needs `gem install erubi -v 1.13.1 && gem install actionview -v 8.1.4`); CI only reads the
  committed files.
- Test sources live in `tests/Campfire.Templates*.Tests/` beside the projects F02 created; no
  csproj outside `src/Campfire.Templates*/` was changed. The generator tests compile the runtime
  from `src/Campfire.Templates/*.cs` in memory, so they need no project reference to it.

## Known gaps

- CRLF handling follows Ruby's parse.y and Prism 1.9 (both read CRLF in a literal as LF), checked
  locally on Ruby 3.3.6; the reference image's Ruby 3.4.10 was not run here. Reference views
  contain no CR, so this only matters for new templates.
- `annotate_rendered_view_with_filenames` (development-only HTML comments) and
  `strip_trailing_newlines` are off in Rails production and not implemented.
