## Notes for dependents

- Namespace `Campfire.Data.Searching` (folder `Search/`): a `Campfire.Data.Search` namespace would
  shadow the `Records.Search` record everywhere under `Campfire.Data`.
- `SearchQuery.Sanitize(q)` is `query`; `SearchQuery.IsPresent` is `present?`;
  `SearchQuery.Searchable(q)` is the query `set_messages` searches for, or null (`Message.none`).
  `SearchQuery.IsWord(Rune)` is `/[[:word:]]/`.
- `MessageSearch.Reachable(session, userId, query)`: `reachable_messages.search(query)
  .last_page_of(100)`, oldest first, the SQL Active Record sends. It throws `SqliteException`
  ("fts5: syntax error near ...") where Rails raises `ActiveRecord::StatementInvalid` (a 500), so
  `set_messages` failing `create` and `clear` too (it's a `before_action`) is M08's to keep.
  Presentation (`with_presentation`) is the caller's.
- `RecentSearches.Record(tx, userId, query, now)` is `searches.record` (find or create, trim to ten
  on create, touch); it throws `ArgumentNullException` for a null query where Rails raises
  `NotNullViolation`. `RecentSearches.Ordered` and `RecentSearches.Clear` are `searches.ordered`
  and `searches.destroy_all`.
- Index maintenance is D02's `Lifecycle/MessageSearchIndex` (create/update/remove after commit,
  from the caller's plain text); D04 searches it and tests it end to end.
- To regenerate: build Ruby 3.4.10, then in `tests/Campfire.Data.Tests/Oracle` run
  `ruby search_word.rb` and `bundle exec ruby search.rb`.
