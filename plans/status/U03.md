## Notes for dependents

- `ForgeryProtection.VerifyViaHeaderOnly`:
  - `Sec-Fetch-Site` header checks: `same-origin` and `same-site` pass; `cross-site`, `none`, or unrecognized values reject with 422 Unprocessable Entity.
  - Missing `Sec-Fetch-Site`: passes only over plain HTTP without forced TLS (`force_ssl`); fails with 422 if HTTPS or forced TLS.
  - `Origin` header check: when present, Origin must match request URL scheme + host + port. Rejects with 422 if mismatched or `null`.
  - `append_sec_fetch_site_to_vary_header` after-action callback appends `Sec-Fetch-Site` to the `Vary` response header (unless authenticated by bot key).
- Default response headers no longer include `X-XSS-Protection` (matching Rails 8.2 defaults).
- Session cookies (`_campfire_session`) containing pre-upgrade Rails sessions with `_csrf_token` continue to decrypt and authenticate seamlessly.
