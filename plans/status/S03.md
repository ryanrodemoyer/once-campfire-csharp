## What was built (`src/Campfire.Storage/Media/`)

- `LibVips`: the system libvips through NetVips (the managed package only, never
  `NetVips.Native`). On first use it applies `vips.rb`: `Vips.block_untrusted(true)` and
  `Vips.block("VipsForeignLoadOpenslide", true)`. It also gives `Version` and `IsAvailable`.
  - **The SQLite clash.** `vips_init` opens its loader modules (`vips-modules-x.y/*.so`) with
    `RTLD_GLOBAL`. The openslide module links the system `libsqlite3`. Its symbols then take over
    the internal PLT calls of the SQLite that Microsoft.Data.Sqlite bundles (`e_sqlite3`).
    `sqlite3_open_v2` runs the system copy's `sqlite3_initialize` and then jumps to a null
    allocator.
  - The result is a segfault, or `vtable constructor failed: message_search_index`, whenever
    libvips loads before SQLite has bound those calls. That would happen in production too, e.g.
    on the first upload before the first search. It's reproduced with `gdb`, and it made
    `bin/check` crash intermittently (exit 139) or fail 52 Storage tests.
  - `LibVips` starts libvips with `VIPSHOME` pointing at a prefix with no modules (set with
    `setenv` before NetVips is touched). It then opens the same module files itself with
    `G_MODULE_BIND_LAZY | G_MODULE_BIND_LOCAL` and makes them resident.
  - Every loader is still registered (heif, jxl, magick, openslide, poppler), and the blocks
    apply after that. Only the modules' libraries stay out of the global scope.
  - `Libvips_modules_are_loaded_without_putting_their_libraries_in_the_global_scope` checks that
    `dlsym(RTLD_DEFAULT, "sqlite3_libversion")` is null, that every module file was opened, and
    that FTS5 works. It fails without the fix.
  - All NetVips calls live in `VipsImaging`, reached only after `LibVips.EnsureInitialized()`.
- `ImageTransformer`: `ActiveStorage::Transformers::Vips` over image_processing 1.14. It reads
  the gem source (`loader(page: 0)`, so no resize-on-load), then:
  - `new_from_file` with `page: 0` only for loaders whose optional inputs include it
    (`select_valid_loader_options`), then `autorot`;
  - `resize_to_limit` → `thumbnail_image(w, height: h, size: :down, no_rotate: true)` and
    `conv(SHARPEN_MASK, precision: :integer)`, with a missing dimension as `MAX_COORD`;
  - `write_to_file("….<format>")` with no options: the saver's defaults, no metadata stripping, its
    own Q.
  - `operations` skips `format` and blank arguments, and refuses `combine_options`. Only
    `resize_to_limit` is supported, which is the only operation Campfire defines.
- `VideoPreviewer`: `ffmpeg -i <input> <Shellwords.split(video_preview_arguments)> -`. stdout goes to
  the preview file. A failure raises `PreviewException`
  (`"ffmpeg failed (status N): <stderr.chomp>"`). `ffmpeg_exists?` is memoized.
- `BlobAnalyzer`: the analyzers in the engine's order (Vips image, video, audio, null).
  - Image analysis uses `new_from_file(access: :sequential)` and swaps dimensions for the four
    rotating EXIF orientations. An error gives `{}`.
  - Video and audio analysis run ffprobe with Rails' argv. Its stderr is inherited, and a missing
    ffprobe gives `{}`. They use Ruby `Float()`/`Integer()` and `.compact`.
  - `Analyze` is `metadata.merge(analyzer.metadata.merge(analyzed: true))`. Existing keys keep
    their place, and Floats are written `320.0` by `RailsJson`.
- `Marcel` and `MarcelMagic.g.cs`: `Marcel::MimeType.for(io, name:, declared_type:)`, by magic
  (the gem's `magic_match_io`, reading only the first bytes any entry can reach) and then
  name/declared type with `most_specific_type`. `marcel_magic.rb` generates the table from marcel
  1.1.0, with the same 464 entries and 279 parents as the Rust port's dump.
- `BlobTempfile`: `blob.open`. It copies the blob to `ActiveStorage-<id>-…<.ext>` with the checksum
  verified, so libvips and ffmpeg see the extension they see under Rails. `Create` is
  `Tempfile.new([prefix, suffix])`.
- `MediaProcessor`: the facade.
  - `TransformVariant` is S02's `VariantTransformer`. It stages `<base>.<format>` with the
    variant's content type, which Marcel identifies again.
  - `RenderPreviewImage` is S02's `PreviewImageRenderer`: `<base>.jpg`, `image/jpeg`.
  - `AnalyzedMetadata` / `AnalyzeAsync` are `blob.analyze`. The file is read outside the writer,
    then `update!(metadata:)` runs.
- `Subprocess`: `IO.popen` without a shell. It has an optional timeout, which Rails doesn't have,
  so it's off by default.

## Notes for dependents

- **Wiring**: `var storage = BlobStorage.Local(root, keys, Marcel.Identify); var media = new
  MediaProcessor(storage);`. Then `variantProcessor.ProcessedAsync(variant, media.TransformVariant)`
  and `ProcessedAsync(preview, media.RenderPreviewImage, media.TransformVariant)`. Pass
  `Marcel.Identify` everywhere `BlobStorage` is built (A06 uploads, A03 avatars and logos), or
  uploads keep S01's declared-type fallback.
- **J lane (AnalyzeJob)**: `BlobAnalyzer.AnalyzesLater(blob)` is `analyzer_class.analyze_later?`.
  It's false only for the null analyzer, which `analyze_later` runs inline. The job calls
  `media.AnalyzeAsync(database, blob)` for unanalyzed blobs, variant images and preview images
  included. Rails analyzes those too, so their vector metadata has `width`/`height`/`analyzed`.
- **Anyone touching NetVips**: go through `ImageTransformer`, `BlobAnalyzer` or `LibVips`, never
  NetVips types directly. Touching NetVips first starts libvips with its modules global, and SQLite
  can then crash (see `LibVips`).
- **P02**: install Debian trixie's `libvips42` (8.16.1-1+deb13u1) and `ffmpeg` (7:7.1.5-0+deb13u1)
  in the runtime stage. Don't install `NetVips.Native`: NetVips loads `libvips.so.42` from the
  system. Then run the Media tests in the image with `CAMPFIRE_REQUIRE_MEDIA_VECTORS=1`, which is
  this task's open criterion. `reference-rust/Dockerfile` builds both from the same Debian source
  packages, with checksums, if apt pinning isn't enough.
- **Timeouts**: Rails waits on ffmpeg and ffprobe indefinitely. `MediaProcessor(storage, toolTimeout)`
  can bound them. That would be a deliberate difference from Rails, so list it in README's Known
  differences if a task turns it on.
- `ImageTransformer.Operations` throws `NotSupportedException` for an operation other than
  `resize_to_limit`. A signed variation key can only carry what the app signed, so only a new
  named variant would reach it.
