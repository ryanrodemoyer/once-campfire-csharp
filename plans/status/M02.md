## What was built

- `src/Campfire.Web/Views/messages/`: `_message`, `_actions`, `_presentation`, `_template`,
  `_unrenderable`, and `boosts/_boosts`, `boosts/_boost`, each a line-for-line translation of the
  ERB (`cache` blocks render their block: a cached fragment holds the same bytes).
- `src/Campfire.Web/Helpers/Messages/`:
  - `MessageView`, `MessageUser`, `MessageRoom`, `BoostView`: what the partials read.
    `content_type`, `sound` and `all_emoji?` (via `StringExtensions.AllEmoji`) are derived from
    them.
  - `MessagesHelper`: `message_presentation` (attachment, sound, or R03's text presentation, with
    the rescue), `message_tag`'s rescue (`_unrenderable` when the creator or a booster is gone, or
    the presentation is unrenderable), `room_display_name`, sound presentation.
  - `AttachmentPresentation`: `Messages::AttachmentPresentation` (video with poster, lightboxed
    thumbnail with Ruby Integer/Float dimension arithmetic, file link with download and share).
  - `MessageJson`: `messages/_message.json`, `messages/boosts/_boost.json` and `users/_user.json`,
    encoded as Rails encodes JSON (a nil creator is `[]`, as jbuilder renders it).
  - `MessageViews`: loads messages as `Message.with_presentation` does (creators, rooms with direct
    room members, bodies, attachments, `boosts.ordered` per message).
  - `DatabaseAttachables`: R03's `IAttachableResolver` over the database (SGIDs verified with the
    app's keys, `GlobalID.find` semantics), producing freshly signed mentions.
  - `Sound`: `reference/app/models/sound.rb`.

## Notes for dependents

- **Rendering a message** (M03 room page, M04 index/refresh, M05 turbo streams, M08 search, RT02
  broadcasts): build the `View` with `RichTextContext = new RenderContext(new DatabaseAttachables(session, keys, now), request.Host)`
  and `Storage` (the app's `BlobStorage`), load with
  `new MessageViews(keys, toPlainText).Load(session, messages)`, then `MessagesMessage(w, message)`.
  The composer template is `MessagesTemplate(w, messageViews.User(currentUser))`. Bot API
  responses use `MessageJson`/`BoostJson` (or the `*JsonObject` forms to embed them in arrays).
- **URLs use the message id; DOM ids use `client_message_id`** (`to_key`), as Rails does.
- **`toPlainText` is R05's** `ActionText::Content#to_plain_text`. `plain_text_body` decides
  `message--emoji`, `/play` sounds and the JSON's `plain_text`, so pass R05's implementation once it
  lands; the tests use the reference's plain text for each seed body.
- In a real request `form_with`/`button_to` include authenticity tokens (`View.FormAuthenticityToken`);
  the renderer the oracle used has forgery protection off, so the vectors have none. W03 already
  checks the token fields byte for byte; M03/M04 replay covers them in full pages.
- `DatabaseAttachables.LocateSigned` reports a signed GID for any model other than an existing user
  as a missing record (Campfire's only attachables are users).
- **Plan change**: M06 owned `Views/messages/boosts/*`, but this task delivers the boost partials
  (`_boost`, `_boosts`), so `plans/tasks.yaml` now gives M02 `Views/messages/boosts/_*` and M06
  `boosts/index*` and `boosts/new*` (commented on M06's issue).

## Known gaps

- "Bot styling" and "edited state" have no markup of their own in the reference: a bot's message
  differs only in its author, and an edited one in `data-message-updated-at`. Both seed cases
  render equal to the reference.
- Fragment caching (`cache [message, "presentation-v3"]`, `cache boost`) isn't modeled: Rails can
  serve a stale fragment where we render fresh bytes. Replay (Q01) runs with fresh caches.
