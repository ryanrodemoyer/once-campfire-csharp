Also covered: writer and reader connections apply `timeout: 5000` and `DEFAULT_PRAGMAS` in
Rails' order. Writes start with `BEGIN IMMEDIATE TRANSACTION`: switching to `BEGIN` fails
`Writes_take_the_write_lock_when_they_begin`. A failed write rolls back and drops its
after-commit work. After-commit work runs in order after the commit, and every action runs even
if one throws. 200 concurrent writes go through a queue of 2. Readers are read-only. Dispose
drains queued writes. The statement cache reuses prepared commands and evicts the least
recently used.

## Notes for dependents

- **Opening.** `SqliteDatabase.Open(new SqliteDatabaseOptions(path))` runs `db:prepare` by default.
  An empty database gets the schema. One that has every migration is left alone. One with missing
  migrations throws `PendingMigrationsException`; migrations aren't ported, so boot Rails on it
  once to migrate it. A non-empty database without `schema_migrations` fails on the first
  `CREATE TABLE` (Rails would `force: :cascade` over it).
- **Writes.** `WriteAsync(tx => ...)` runs on the single writer thread in an immediate
  transaction. The queue is bounded (`WriteQueueCapacity`, 256), and callers wait for room when it
  is full. `tx.AfterCommit(session => ...)` queues work for after the commit (D03's callbacks).
  Never await another write from inside a write.
- **Reads.** `ReadAsync(session => ...)` takes a free connection from `Readers` read-only
  connections (10, Rails' default pool) and runs on the caller's thread.
- **SQL.** Use `session.Execute`, `Scalar<T>` and `Query(sql, map, ("@name", value)...)`, or
  `session.Command(sql, ...)` for a raw reader. Statements are prepared once per connection and
  cached (1000 per connection, Rails' `statement_limit` default). Don't dispose a command from
  `Command`. Parameters must be named (`@x`, `$x`, `:x`), because Microsoft.Data.Sqlite can't bind
  anonymous `?`. `null` binds as SQL NULL.
- **Column order.** `RailsSchema.Statements` is the `db:prepare` schema, with alphabetical
  columns. Databases that Rails built by migrating keep migration column order, so select
  columns by name and never read by position over `*`.
- **SQLite.** Microsoft.Data.Sqlite 10.0.12 with the bundled e_sqlite3 (SQLite 3.53.3, FTS5
  compiled in). `mmap_size` is set as Rails sets it. The Rust port dropped it for throughput, so
  revisit it in benchmarking (B lane) with evidence, and record it as a known difference if it
  changes.
- **Timestamps.** `SchemaPreparer` formats `ar_internal_metadata` times like `Quoting#quoted_date`:
  UTC `yyyy-MM-dd HH:mm:ss`, plus `.ffffff` only when there are microseconds. D02's record
  timestamps need the same rule. It is private here; move it to RailsCompat or D02 when needed.
- **Oracle.** To regenerate: `cd tests/Campfire.Data.Tests/Oracle && bundle install && bundle exec
  ruby generate.rb`. It needs Ruby; the C# tests don't. `rails-fixtures.sqlite3` is force-added
  because `.gitignore` ignores `*.sqlite3`.

## Outside `owns`

The deliverable requires a package, so this PR adds `Microsoft.Data.Sqlite` to
`Directory.Packages.props` and `src/Campfire.Data/Campfire.Data.csproj` (F02's paths; F02 is done).
That is one line in each. Tests live in `tests/Campfire.Data.Tests/{Schema,Sqlite,Oracle}/` and
`TestDatabase.cs`, which no task owns.

## Known gaps

- No custom WAL checkpointer. SQLite's auto-checkpoint is kept, as in Rails. The Rust port's
  background checkpointer is a throughput change for the benchmark lane to weigh.
- The Rust port's extra `index_messages_on_room_id_and_created_at` is not added: it would make
  `.schema` differ from Rails. Leave it for a benchmark task to propose, as a known difference.
