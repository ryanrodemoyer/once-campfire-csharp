## What was built (`src/Campfire.Storage/Blobs/`)

- `BlobStorage`: the facade. `BlobStorage.Local(root, keys)` is Campfire's `local` Disk service
  with `ActiveStorage.verifier` (`message_verifier("ActiveStorage")`).
  - `Stage(stream | UploadedFile, ...)` is the file half of `build_after_unfurling` + upload: a new
    key, the bytes copied to `path_for(key)` while their MD5 and size are computed, the content type
    (identified unless a declared type is trusted with `identify: false`), and
    `metadata: {"identified": true}`. It returns a `StagedBlob`; disposing it deletes the file unless
    the row committed.
  - `Create(tx, staged, now)` is `create_and_upload!`'s row. `AttachOne(tx, staged | blob, recordType,
    recordId, name, now, touchRecord)` is `record.<name> = attachable` for `has_one_attached` inside
    the record's transaction: it destroys the current attachment row, inserts the blob and the new
    attachment, and returns the replaced blob id for `purge_later`. Both keep the staged file once
    the write commits (`tx.AfterCommit`).
  - `Url(blob, baseUrl, expiresAt, disposition)` is `blob.url` with `content_type_for_serving` and
    `forced_disposition_for_serving`. `DeleteFiles` is `Blob#delete`, legacy `variants/<key>/` included.
    `VerifyIntegrity` is `blob.open`'s checksum check.
- `DiskService`: `path_for` (`<root>/ab/cd/<key>`), `upload` with checksum verification,
  `download`, `delete`, `delete_prefixed`, `exist?`, the disk URL and direct upload paths, and
  `DiskController`'s `decode_verified_key` / `decode_verified_token`.
- `BlobUrls`: `signed_id` / `find_signed` (purpose `blob_id` on `ActiveStorage.verifier`, not the
  Active Record signed id verifier), `rails_blob_path`, `rails_storage_proxy_path`, and the
  representation paths given a variation key.
- `BlobRecords`: SQL for `active_storage_blobs` and `active_storage_attachments` (insert, find by
  id, key or record, attachments of a blob, metadata update, delete attachment, purge's row delete).
- `Filename`, `ContentDisposition` (with I18n's approximation table, generated by
  `Oracle/approximations.rb` from i18n 1.14.7), `RouteEscaping` (Journey's `escape_path` /
  `escape_segment`), `BlobKey` (`SecureRandom.base36(28)`, base64 MD5), `BlobContentTypes`.

## Notes for dependents

- **Upload order.** Rails inserts the rows in the record's transaction and uploads after commit.
  Here the file is staged first, outside the writer, and kept on commit; a rollback or failed copy
  leaves neither file nor row. The committed result is identical. Usage:
  `using var staged = storage.Stage(upload); await db.WriteAsync(tx => BlobStorage.AttachOne(tx, staged, ...));`.
- **Touches and jobs are the caller's.** The attachment's `belongs_to :record, touch: true` needs the
  record's model, so `AttachOne` calls `touchRecord` after each attachment change; D03's callbacks
  supply it (Message touches its room in turn). After commit Rails enqueues `AnalyzeJob` for
  unanalyzed blobs and `PurgeJob` for `ReplacedBlobId`; those are the J lane's.
- **Content type identification** is a `ContentTypeIdentifier` delegate. Until S03 ports Marcel it
  returns the declared type (or `application/octet-stream`), which is what Marcel returns for every
  upload in the vectors.
- **S02** passes its variation key to `BlobUrls.RepresentationRedirectPath` / `ProxyPath`, and can
  use `BlobRecords` and `BlobStorage.Create`/`AttachOne(tx, blob, "ActiveStorage::VariantRecord", id,
  "image", ...)` for variant images. **S05** uses `DiskService.DecodeVerifiedKey/Token`,
  `BlobUrls.VerifySignedId`, `ContentDisposition` and `BlobStorage.Url`.
- `ContentDisposition` is `ActionDispatch::Http::ContentDisposition`, useful to any `send_file`.
  No task owned it, so it lives here; move it to RailsCompat if another lane needs it without
  Storage.
- Shared file touched: `tests/Campfire.Storage.Tests/Campfire.Storage.Tests.csproj` (F02's, done)
  gains a reference to `tests/Campfire.Vectors`. The oracle lives in
  `tests/Campfire.Storage.Tests/Oracle/` (`bundle install` there, then `./run.sh`).
