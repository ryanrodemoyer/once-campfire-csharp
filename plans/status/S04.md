## Notes for dependents

- `Campfire.Web.QrCode.QrCodeSvg.Render(ReadOnlySpan<byte>)` returns exactly what
  `RQRCode::QRCode.new(url).as_svg(viewbox: true, fill: :white, color: :black)` renders. Pass it the
  bytes of `Base64.urlsafe_decode64(params[:id])`. It returns null when the data needs more than
  version 40 holds. Rails raises `RQRCode` "Data length exceed maximum capacity of version 40" in
  that case, which is a 500. A08 owns the controller: the content type (`image/svg+xml`), the
  `Cache-Control` from `expires_in 1.year, public: true`, and the decode error handling.
- This port follows the gem, not the QR spec's optimal choices: a single segment (numeric, then
  alphanumeric, then byte), level H, the first version whose capacity is *strictly* greater than the
  bits needed, and the first mask with the fewest lost points as the gem scores them, including
  the Float dark-ratio term. It is a C# translation of the Rust port's
  `crates/campfire/src/controllers/qr_code/rqrcode.rs`, which ports rqrcode_core 2.1.0 and
  rqrcode 3.2.0 (the versions in `reference/Gemfile.lock`).
- Shared file touched: `tests/Campfire.Web.Tests/Campfire.Web.Tests.csproj` (F02 owns it, and
  F02 is done) gains a `ProjectReference` to `tests/Campfire.Vectors` so the tests can read the
  vectors.
