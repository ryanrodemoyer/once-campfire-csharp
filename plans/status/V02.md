## What landed

- `parity/bin/seed`: the Rust port's seed builder with the same `build` and `list` commands, plus
  `hash` and `verify`. It builds the Rust port's seed scripts in place,
  `reference-rust/parity/seeds/*.rb` (`build.rb`, `lib/seed.rb`, `default.rb`, …). It doesn't copy
  them, so the C#, Rust and Go benchmarks all run on the same data. Each seed lands in
  `parity/.seed/NAME/{db/production.sqlite3, storage/, labels.json}`. `parity/bin/reference`,
  `compose.parity.yml` and the Rust bench harness (`bench/lib/benchlib.py`) already read that
  layout.
- `parity/.seed/SEED.sha256` (committed): one sha256 per file in the `default` seed. `build`
  rewrites the lines for the seeds it built (`SEED_RECORD=0` leaves the file alone). `verify`
  diffs the built seeds against the file.
- The database is hashed as its SQL dump (`sqlite3.iterdump`, recorded as
  `default/db/production.sqlite3.sql`). Two builds produce `production.sqlite3` files that differ
  in 15 bytes. Those bytes are build-time wall-clock timestamps (`2026-10-05 19:13:45.502` vs
  `19:14:05.120`) in freed pages. Every row and the whole schema are equal, so the dumps match.
  Every other file (`labels.json` and the 14 Active Storage blobs and variants) is hashed byte
  for byte.

## Notes for dependents

- **Q01 / B01**: use `parity/bin/seed build default`, then `parity/bin/seed verify`, to check
  that a benchmark or replay runs on the recorded seed. Labels are documented in
  `reference-rust/parity/seeds/README.md`. The seed clock is `NOW` = 2026-03-02 16:00:00 UTC
  (`labels.clock.now`).
- `parity/bin/seed build` with no names builds every seed (`default`, `first_run`,
  `custom_styles`, `restricted`, `crowd`) and records all of them.
- Native runtime setup in this sandbox: Ruby 3.4.10 was compiled from the `v3_4_10` git tag,
  because `cache.ruby-lang.org` is blocked. rsync came from the Ubuntu archive.

## Known gaps

- **The recorded hashes come from the native runtime.** Docker can't build here because
  `deb.debian.org` is blocked, the same as in V01. The DB dump and `labels.json` don't depend on
  the runtime. The media variants and the video poster come from libvips/ffmpeg: the host has
  libvips 8.15.1 and ffmpeg 6.1.1, and the reference image has other versions. Once someone builds
  the seed under Docker (a CI runner or a workstation), run `parity/bin/seed build default` and
  commit the updated `SEED.sha256` (B01 or B05 at the latest, before any numbers are published).
