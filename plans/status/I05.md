## What was built

- `src/Campfire.Jobs/Webhooks/WebhookClient.cs` is `Webhook#deliver`'s HTTP half: an
  unrestricted handler, Net::HTTP's headers, 7-second connect and per-read timeouts, gzip and
  deflate inflated by hand, `content_type` as Net::HTTP parses it, then text, attachment or no
  reply.
- `src/Campfire.Jobs/Webhooks/WebhookMimeTypes.cs` is `Mime::Type.lookup`.
- `src/Campfire.Jobs/Webhooks/BotWebhooks.cs` is `Bot::WebhookJob`. `RegisterWith(JobRunner)`
  registers it. It loads the bot, message, room and webhook, builds `payload`, delivers, and hands
  the reply to `IWebhookReplies`.
- `src/Campfire.Web/Controllers/Messages/ByBotsController.cs`
  (`Messages::ByBotsController`), `Boosts/ByBotsController.cs`
  (`Messages::Boosts::ByBotsController`), `ByBotsRoutes.cs`, and `ByBotsWebhookReplies.cs`
  (`IWebhookReplies`: the reply message and its renderer-style `broadcast_create`).
- `src/Campfire.Web/Views/messages/by_bots/ByBotsJson.cs` and
  `Views/messages/boosts/by_bots/BoostsByBotsJson.cs` hold the jbuilder views, over M02's
  `MessageJson`.

## Notes for dependents

- **Server wiring:** nothing registers job handlers with the server's `JobRunner` yet (I02's
  `MessagePusher` isn't wired either). Whoever wires them should register
  `new BotWebhooks(database, new WebhookClient(), new ByBotsWebhookReplies(webApp), session => new DatabaseAttachables(session, keys, clock.GetUtcNow())).RegisterWith(runner)`.
- **M10:** the attachment paths are partial-method hooks, as in `MessagesWriteController`.
  `MessagesByBotsController.CreateWithAttachment` and `DestroyWithAttachment` answer 501 without
  them. `ByBotsWebhookReplies.CreateAttachmentReply` fails the job without it. The details are on
  #126.
- **Q02:** every bot API route is bound; the only 501s left are the attachment paths above.

## Known gaps

- **Attachments** (M10, see above): multipart `attachment` creates, destroying a bot message
  with a file, and attachment replies from webhooks.
- **A multipart body without an `attachment` part.** Rails uses the raw multipart text as the
  message body. C05's `ParsedBody.Raw` doesn't keep multipart bodies, so the port sees an empty
  body and answers 422. No real bot client sends this.
- **Fragment caching** (M02's gap): with the clock frozen, a message updated twice keeps its
  cache key, so the reference served stale `json.cache!` JSON. The oracle clears `Rails.cache`
  before each request.
- **Unbounded reply size and delivery time:** as in Rails, the reply is read whole and only each
  read is timed. The Rust port caps both; this port doesn't, to stay equal to the reference.
