  - Oracle: `tests/Campfire.RichText.Tests/NullByte/generate.rb`, run in the reference image with

    `&#0;` in an attribute becomes U+FFFD.
  - `dotnet test` (RichText.Tests, filter `NullByte`): `SetAttribute_matches_nokogiris_assignment` and
    `Parsing_replaces_or_drops_a_nul_as_nokogiri_does`, 15 cases, pass.

## Notes for dependents

- `HtmlElement.SetAttribute` (`src/Campfire.RichText/Html/HtmlNode.cs`) raises
  `RichTextRaisedException("ArgumentError: string contains null byte")` when the name or the value holds a NUL,
  before it stores anything. Every caller now gets Nokogiri's behavior, including R05's
  `RichTextPlainText` and `EditableContent` call sites.
- `NokogiriAttribute` (R04's call-site workaround) is deleted. Its three callers (`SafeListSanitizer`,
  `ContentFilters`, `RichTextRenderer`) call `SetAttribute` directly.
- Parse-time NUL handling is unchanged.
