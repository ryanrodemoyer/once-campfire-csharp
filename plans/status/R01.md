## What was built

- **Gumbo, ported** (`src/Campfire.RichText/Html/Gumbo/`): the tokenizer (`tokenizer.c` and the
  UTF-8 iterator's CR/LF and BOM handling) and the tree builder (`parser.c`), state by state, from
  the gumbo-parser sources inside the nokogiri 1.19.4 gem that `reference/Gemfile.lock` pins. The
  named character references are generated from its `char_ref.rl`. The plan allowed AngleSharp or
  a port of the Go tree builder; neither matches Nokogiri: Gumbo stops at its 400-element depth
  and 400-attribute limits while parsing (the result depends on when it checks, see
  `HtmlParserTests`), keeps `<template>` contents as children, still has the legacy select
  insertion modes, buffers text until the next insertion, and, built without `NDEBUG` as Nokogiri
  builds it, drops the attributes of an `<a>` or `<nobr>` start tag the adoption agency ignores.
  Porting the oracle gets all of that for free.
- **libxml2's view of the tree** (`HtmlParser`): what nokogiri's `gumbo.c` `build_tree` makes of
  Gumbo's output: adjacent text merged (`xmlAddChild`), text under a document dropped, CDATA
  nodes, the doctype as a document's first child, `xlink:`/`xml:`/`xmlns:` attributes with a
  prefix.
- **Serializer** (`HtmlSerializer`): `html_standard_serialize` from nokogiri's `xml_node.c`:
  attributes in order, always double-quoted, escaping `&`, U+00A0 and `"`; text escaping `&`,
  U+00A0, `<`, `>`; raw text in HTML `style script xmp iframe noembed noframes plaintext
  noscript`; void HTML elements (`area base basefont bgsound br col embed frame hr img input keygen
  link meta param source track wbr`) without an end tag; comments, CDATA and doctype verbatim.

## Notes for dependents

- API (`Campfire.RichText.Html`): `HtmlParser.ParseFragment(html, context?)` is
  `HTML5::Document#fragment` (body context); pass `FragmentContext.For(node)` for `Node#fragment`,
  which `inner_html=` and `replace` use (context name and namespace, form ancestor,
  annotation-xml encoding, quirks mode). `HtmlParser.ParseDocument` is `Nokogiri::HTML5.parse`
  (for I03's opengraph). Both throw `HtmlParseException` where Nokogiri raises `ArgumentError`.
  Callers strip input themselves, as `ActionText::Fragment.wrap` does with `String#strip`.
- DOM: `HtmlFragment`/`HtmlDocument`/`HtmlElement` (`HtmlParentNode`: `Children`, `Descendants()`,
  `AppendChild`, `InsertBefore`, `InsertAt`, `RemoveChild`, `ReplaceChild`), `HtmlText`,
  `HtmlCData`, `HtmlComment`, `HtmlDoctype`. `HtmlElement.SetAttribute` is Nokogiri's `node[name]=`
  (update in place or append). Attributes are `HtmlAttr` (`Prefix`, `Name`, `Value`,
  `QualifiedName`); Loofah's attribute name for a prefixed attribute is `QualifiedName`.
  `node.ToHtml()` is `to_html`; `HtmlSerializer.SerializeChildren` is `inner_html`.
- The Rust port escapes `<` and `>` in attribute values in the presentation on purpose (a listed
  known difference about rails_autolink); the serializer here is Nokogiri's exactly. If R02 adopts
  that difference it needs a serializer option, which is a small change in this directory.
- `tests/Campfire.RichText.Tests/Campfire.RichText.Tests.csproj` (F02's) gained a reference to
  `tests/Campfire.Vectors`, which the corpus test loads.
- Regenerate the Gumbo oracle with `tests/Campfire.RichText.Tests/Html/Oracle/generate.py` (needs
  python3, curl, git and a C compiler); CI only reads the committed `gumbo-trees.jsonl`. R04 can
  reuse `gumbo_dump.c` for differential fuzzing.

## Known gaps

- Parse errors and source positions aren't recorded (Action Text and Loofah don't read them), and
  Nokogiri's `parse_noscript_content_as_text` option isn't offered (nothing sets it).
- Invalid UTF-8 can't reach the parser: a .NET string is already decoded. A lone surrogate is read
  as U+FFFD, as Gumbo reads an invalid byte.
