## What landed

- `bench/bin/run` is `reference-rust/bench/run` with a `csharp` app (`CSHARP_IMAGE`, default
  `campfire-csharp:app`). It keeps the same seed, the same load generator built from
  `reference-rust/bench/loadgen`, `--cpuset-cpus` / `taskset` pinning, the quiet-load wait,
  alternating sequential reps, c=1/16/64, and the cable, upload and memory suites. `rust` can be
  added as a third column. New options: `--routes`, `--suites`, `--up-only` and `--oracle`.
- **Response validation** (`bench/lib/validate.py`). Neither the Rust runner nor the Go runner
  does this against Rails:
  - every GET route must have the reference's status, content type and body, with only the CSRF
    tokens blanked;
  - every measured response must have the validated status, with no transport errors;
  - posts must be saved and indexed (the Go harness's check);
  - every cable client must subscribe and every message must arrive everywhere;
  - every upload's thumbnail must be served.

  The first failure stops the run, writes the reason to `failed.txt` and records no numbers for
  that app.
- `bench/bin/report` prints the README table format first (requests/sec at 16 clients, Rails / C#
  / Rust columns), then the Rust report's median [min–max] tables with a "C# adv." column. It
  flags runs that stopped early or weren't validated.
- `bench/README.md` covers how to run, what is validated and what the results directory holds.

## Split

The original criterion ("`bench/run --apps reference,csharp` completes on /up-only") can't be met
by B01. The C# app has no `/up` until A08, which is blocked behind W02 and S04. Running the
reference also needs a Docker host that can build `campfire-reference:app`. That criterion is now
**B06**, "First /up-only harness run against Rails" (deps B01 and A08; owns
`bench/results/harness-*`, which moved from B01). B05 depends on B06. B02 doesn't, because it
doesn't measure `/up`.

## Notes for dependents

- **B02/B04/B05**: `bench/bin/run --apps reference,csharp` runs everything. Results go in
  `bench/results/<stamp>`, or wherever `--out` points (for example `bench/results/first-<date>`).
  The reference must come first in `--apps` (it captures the oracle), or pass `--oracle DIR`.
  `bench/bin/report DIR` reprints the tables.
- **The C# container**: it gets `PORT`, `HTTP_PORT` and `TARGET_PORT` (`--network host`). Without
  Thruster it listens on `PORT`. When P03 adds Thruster, Thruster takes `HTTP_PORT` and gives the
  app `TARGET_PORT` as `PORT`, so the harness needs no change. Volumes are `/rails/storage/db` and
  `/rails/storage/files`, as in P01.
- **Process memory roles**: the report reads the C# server as the role `campfire` (the
  `/usr/local/bin/campfire` link from P01), plus `thrust` once P03 adds it. Roles come from
  `reference-rust/bench/lib/procmem.py`. If the process name changes, update `APP_ROLE` and
  `SERVING_ROLES` in `bench/bin/report`.
- **Normalization** blanks only `csrf-token` meta values and `authenticity_token` form values.
  Anything else that differs fails the run. That is deliberate: it is the "any difference is a
  bug" rule.
- `CGROUP_PARENT` (default `/sys/fs/cgroup/system.slice`) is where Docker puts
  `docker-<id>.scope`. Change it for a cgroupfs-driver host.
- Scratch space is `tmp/bench/` (gitignored): the load generator's cargo target and per-app
  storage copies.
