## Notes for dependents

Namespace `Campfire.Web.Routing`, plus the generated `Campfire.Web.Routes`.

- **Binding a handler** (every feature task): in your own file, implement the endpoint's hook as
  shown above. Hook names are the endpoint in PascalCase: `users/push_subscriptions/test_notifications#create`
  is `UsersPushSubscriptionsTestNotificationsCreate`. `Routes.g.cs` lists each hook with its routes. A
  handler is a plain `RequestDelegate`. Routes that share an endpoint (PATCH and PUT, the two
  Active Storage redirect routes) share one hook.
- **Per request**: `context.RailsRequest()` returns the `RailsRequest` the router installs. It
  exposes:
  - `Method` (after `_method`), `WireMethod`, `IsHead`
  - `Path` (normalized) and `OriginalPath` (raw `PATH_INFO`)
  - `Route` and `PathParameters` (defaults, then controller and action, then captures, as Rails orders them)
  - `Body` (C05's `ParsedBody`, parsed once and disposed after the request), `QueryParameters`
  - `Parameters` (`params`: body, then query, then path)
  - `Formats`/`Format`/`NegotiateMime(order)` (for `respond_to`), `ContentMimeType`, `Accepts`
  - `IsXhr`, `IsTurboFrameRequest`/`TurboFrameRequestId`

  JSON `wrap_parameters` is controller-level and left to W02.
- **Errors**: throw anything implementing `IHasHttpStatus` (or C05's param exceptions) and the
  router renders Rails' response for it (`ErrorPages`). D02's record-not-found should implement
  `IHasHttpStatus` with 404. Built in: `RoutingErrorException` (404), `BadRequestException` (400),
  `UnknownHttpMethodException` (405), `InvalidMimeTypeException` (406), `NotImplementedRouteException`
  (501). Anything else is a 500. An exception after the response has started propagates.
- **URL helpers**: `Routes.RoomPath(room)`, `Routes.RoomUrl(origin, room)` and so on, one pair per
  named route, taking the required segments positionally as `object?`. Routes with a default
  segment get an extra overload without it: `Routes.UserSidebarPath()` is `/users/me/sidebar`.
  - Records passed as segments or query values should implement `IToParam`.
  - Keyword options go in `RouteOptions` (`new() { { "q", query } }`): query params, `format`,
    `anchor`, and `host`/`protocol`/`port` for `_url`. Other reserved options throw rather than being ignored.
  - `UrlBase` is the request's protocol, host and optional port (`SetCurrentRequest#default_url_options`
    plus `request.optional_port`). W02 should build it from the request.
  - Direct routes: `Routes.FreshAccountLogoPath(accountUpdatedAt, size)` and
    `Routes.FreshUserAvatarPath(avatarToken, updatedAt)`, plus their `_url` forms.
  - Generation follows Rails' unoptimized path, which is the one the app always takes because
    `default_url_options` is never empty there. Recall of the current request's path parameters
    isn't modeled: it only matters when a required segment is omitted, which the typed helpers don't allow.
- **Wiring**: `new Router(Routes.Table, ErrorPages.FromDirectory(publicDir), uploadDirectory)` and
  `app.Run(router.HandleAsync)`. `src/Campfire.Server/Program.cs` belongs to P01, so it still has
  the placeholder. Put `StaticFiles.TryServeAsync` (F04) in front of the router, as Rails does.
- **Regenerating**: `Routes.g.cs` comes from `UPDATE_ROUTES=1 dotnet test tests/Campfire.Web.Tests
  --filter RoutesSourceTests`. Its input, `Vectors/routes.json`, comes from `Vectors/generate.rb`
  (instructions in its header).

## Known gaps

- Framework routes have no handlers and answer 501 until a task binds them: turbo-rails' native
  navigation (`turbo/native/navigation#*`), Action Mailbox's ingresses and conductor, and Active
  Storage's controllers. Active Storage belongs to S05/S-lane tasks. `rails/health#show` (`/up`)
  belongs to A08. Q-lane replay will flag the native-navigation and mailbox routes. Actions the
  reference doesn't define (for example `first_runs#edit`, which is `AbstractController::ActionNotFound`,
  a 404) are also 501 stubs until Q02 classifies them, as its card says.
- Ruby's `\w` in the path-extension check and `\Z` in route regexes match the same inputs here only
  because request targets are ASCII. A raw non-ASCII request target hasn't been tested against Kestrel.
- HEAD bodies: the router sends no body for HEAD error pages. For handler responses it relies on
  Kestrel dropping body writes for HEAD, as `Rack::Head` does. Q-lane replay should confirm the headers.
