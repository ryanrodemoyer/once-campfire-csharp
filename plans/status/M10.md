## Notes for dependents

- `MessagesWriteController.CreateWithAttachment` and `DestroyWithAttachment` are implemented. A multipart `attachment` (an upload or a blob signed id) creates the message, the blob and the attachment in one transaction, keeps the file after commit, enqueues `ActiveStorage::AnalyzeJob`, then runs `process_attachment` (analyze, then the `:thumb` or the video preview) before the broadcasts M05 already sends.
- `MessagesByBotsController` has the same two hooks (top-level `attachment`, no body, no client message id). `ByBotsWebhookReplies.CreateAttachmentReply` does `Blob.create_and_upload!` (Marcel still identifies the bytes) and then `create_with_attachment!`.
- `MessageAttachmentLifecycle.DestroyWithAttachment` (in `src/Campfire.Data/MessageAttachments/`) is the shared destroy: the attachment row in the message's transaction, then `ActiveStorage::PurgeJob`. `MessageAttachmentJobs.RegisterWith(runner)` performs `ActiveStorage::AnalyzeJob` and `ActiveStorage::PurgeJob`. Nothing registers it with the server's runner yet, same as the other job handlers.
- Derivative bytes match the reference only under the pinned toolchain (P02). Anywhere else the replay still checks rows, with checksum and size of generated blobs read as placeholders.

## Known gaps

- `RemoveBannedContentJob` still calls `MessageLifecycle.Destroy`, so a banned user's message that has a file keeps its attachment row and nothing enqueues `PurgeJob`. The shared destroy is `MessageAttachmentLifecycle.DestroyWithAttachment`. I01 owns `src/Campfire.Jobs/RemoveBannedContent.cs`; the job has a broadcaster and no job queue, so it needs `DomainSeams` (or an `IJobQueue`) before it can call the shared destroy. Noted on #30.
- `rooms#destroy` still answers 501 when a message in the room has an attachment (`Rooms::SettingsController`). M07 owns that controller; noted on #63 and the merged PR #136. Replacing the per-message `MessageLifecycle.Destroy` with `MessageAttachmentLifecycle.DestroyWithAttachment` lifts it. There is no README "Known differences" entry for it.
- Replacing a message's attachment on update (`MessagesController#update` and the bot API) still throws `NotImplementedRouteException`. The reference's file uploader creates messages; it does not replace. No caller in the app posts an attachment on update.
