## Acceptance evidence

- [x] A transfer link minted on Rails works on C# and vice versa
  - **The oracle.** `tests/Campfire.Web.Tests/Controllers/Profiles/Vectors/generate.rb` runs in
    the reference app (`parity/bin/reference runner --storage tmp/a02 --time 2026-03-02T16:00:00Z
    --freeze`, Docker runtime, `campfire-reference` image) on a copy of D02's parity seed. It
    records the transfer ids Rails mints at the frozen time for David, Kevin, Jason, Lou and
    Bender Bot (`user.transfer_id`), then sends 61 requests in order straight to
    `Rails.application` with CSRF protection on, and records each response (status,
    `content-type`, `location`, `vary`, `cache-control`, `set-cookie`, `x-frame-options`, body),
    its broadcasts and jobs, and every changed row of `users`, `sessions` and the Active Storage
    blob and attachment tables. Output: `Vectors/profiles.json`.
  - **Rails-minted links on C#.** `ProfilesReplayTests.Each_request_answers_and_changes_what_the_reference_did`
    replays every request through the router and pipeline: the transfer page (signed out, signed
    in, a bad id, JSON and `.json` 406s), and `PUT`/`PATCH` with Rails' links: Kevin, Lou, Jason
    and a bot are signed in (a new `sessions` row and `session_token` cookie, 302 to the root, or
    to `return_to_after_authenticating` when the session holds one), the same link works twice,
    a link one second from expiry works; an expired link, a tampered one, an avatar token (wrong
    purpose), a garbage id, and good signatures for a deactivated, banned or missing person all
    answer `head :bad_request`; no CSRF token is a 422.
  - **C#-minted links on Rails.** `ProfilesReplayTests.Transfer_ids_minted_here_are_the_ones_the_reference_mints`:
    `TransferableUser.GenerateTransferId` at the same instant produces exactly the string Rails
    minted for each user (so Rails verifies it as its own), and `VerifyTransferId` reads it back.
    The profile pages in the replay also carry the C#-minted
    `session_transfer_url(user.transfer_id)` and are byte-equal to Rails' (with CSRF masks as
    placeholders).
  - Profile: `/users/:user_id/profile` shows and updates the signed-in person whatever id the URL
    names. The replay covers the page for an administrator, a member, someone in no rooms,
    someone with an avatar (delete button), referers (`link_back`), Safari (install
    instructions), JSON 406, signed out; the resource routes without actions (404); updates of
    name, bio, blank bio, password (blank leaves it), email address, a taken address (500, as
    `ActiveRecord::RecordNotUnique`), unpermitted role, a missing `user` (400), `user` as a
    string (500), an array name (dropped by `permit`), no CSRF token (422), signed out; and the
    avatar: upload, replace, `""` (removes it via A06's `UsersAvatarsController.DetachAvatar`),
    `""` with none, a bad signed id (500), and a blob's signed id (attaches that blob). The flash
    notice ("✓", or the 30-minute one whenever an avatar param is sent) is compared in the
    session cookie.
  - `bin/check` green.

## Notes for dependents

- `SessionsTransfersController` (`Show`, `Update`) and `UsersProfilesController` (`Show`,
  `Update`) are wired in `Controllers/Sessions/TransfersRoutes.cs` and
  `Controllers/Users/ProfilesRoutes.cs`; profile `new`/`edit`/`create`/`destroy` raise
  `ActionNotFound` as in Rails.
- `ProfilePage` and `ProfileMembership` (`Views/users/profiles/show.cs`) are the view models.

## Known gaps

- Active Storage's `AnalyzeJob` (after an upload) and `PurgeJob` (for a replaced or removed
  avatar) are recorded in the vectors but not compared; the C# port doesn't enqueue them as seam
  events yet (same as A03 and A06).
- The profile page always renders in the application layout; a Turbo Frame request for it would
  get the frame layout in Rails (not exercised by the frontend).
