## What landed

- `parity/state/dump.py`: Core normalizer and dumper for SQLite database tables and Active Storage file trees.
  - Dumps tables in deterministic order, columns in sorted order, and rows sorted by primary key or deterministic composite keys.
  - Masks and canonicalizes non-deterministic fields: bcrypt hashes (`«bcrypt:cost»`), tokens (`«token»`), client message UUIDs (`«uuid»`), deactivated emails (`«email:masked»`), timestamps (`«t-…s»`, `«t:live»`), and canonical JSON settings.
  - Dumps Active Storage file trees with relative paths and SHA-256 content hashes, ignoring transient SQLite journaling files (`-wal`, `-shm`).
- `parity/state/diff.py`: State differential engine comparing SQLite databases and storage directories.
  - Emits structured and human-readable diff reports highlighting missing rows, extra rows, modified columns, missing blobs, extra blobs, and modified files.
- `parity/state/defects.py`: Planted defect injector for self-testing mutation checks (`missing-row`, `extra-row`, `modified-row`, `missing-file`, `extra-file`, `modified-file`).
- `parity/state/test_state.py`: 13 offline unit tests covering normalizer rules, database dumping and sorting, storage tree hashing, diffing, and defect detection.
- `parity/state/rollback.rb`: Script executed by Rails runner verifying that the reference Rails Active Record models read, edit, delete, and search a message written by C#, and verify boosts, user, session, search, closed room, and account settings.
- `parity/state/scenario.rb`: Scenario runner driving mutating actions against both reference and candidate.
- `parity/state/run`: Command-line executable implementing `--diff`, `--dump`, `--rollback`, `--scenario`, `--replay`, and `--selftest`.
- `tests/Campfire.Data.Tests/State/StateDifferentialTests.cs`:
  - `ExportDatabaseForRailsAsync`: Exports a C#-written database on top of `rails-fixtures.sqlite3` with message, rich text, boost, user, session, search query, closed room, and account settings.
  - `Exported_database_contains_expected_csharp_entities`: Asserts database integrity from C#.
  - `Rails_on_csharp_data_reads_edits_deletes_and_searches`: Boots `campfire-reference` container on C#-written state and runs `rollback.rb`, confirming Rails successfully reads, edits, deletes, and searches the message C# wrote.
  - `Schema_identity_matches_rails_prepared_schema`: Verifies SQLite schema definition compatibility against `rails-schema.sql`.
