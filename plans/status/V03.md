## Notes for dependents

- **Reference** `tests/Campfire.Vectors/Campfire.Vectors.csproj` from your test project and write
  `[MemberData(nameof(RailsCompatVectors.SignedCookieVerify), MemberType = typeof(RailsCompatVectors))]`.
  Classes: `RailsCompatVectors`, `RubyCoreVectors`, `CampfireVectors` (routes, sessions, user
  agents), `StorageVectors`, `RichTextVectors`, `IntegrationVectors` (opengraph, webhook),
  `QrCodeVectors`. Whole files are available as `File` / `*File` for one-off values such as
  `RailsCompatVectors.File.SecretKeyBase` or `RailsCompatVectors.File.Session`.
- **Families are methods, not properties.** xunit.analyzers 1.27 crashes (AD0001, "Sequence
  contains no elements") on `[MemberData]` naming a property or field declared in another
  assembly; methods work.
- **Strict parsing.** Records cover every JSON property (`UnmappedMemberHandling.Disallow`), and
  non-nullable members must be present and non-null, so a regenerated vector that changes shape
  fails to load instead of silently dropping data. Values Ruby returns in several shapes stay
  `JsonElement`; `RubyResult<T>` is a value or `{"error": "..."}`; rich text's `Outcome<T>` is
  `{"ok": ...}` or the raised error and message.
- **Files beyond the card**: `rqrcode.json` (S04's vectors, from `reference-tools/campfire/rqrcode.rb`)
  is imported too. `richtext/inputs.yml` is the generator's input and is not parsed;
  `expected.json` carries every case's body.
- **reference-tools/** is a verbatim copy (plus the opengraph and webhook oracles in `oracle/`)
  and still assumes the Rust layout; V01 adapts it. It is not covered by the manifest so V01 can
  edit it freely.
- **Shared files touched**: one `PackageVersion` (`xunit.v3.extensibility.core` 3.2.2, the version
  `xunit.v3` already pulls in) in `Directory.Packages.props` and the two new projects in
  `Campfire.slnx`, both F02-owned (F02 is done); without them the loader can't use `TheoryData`
  and its tests wouldn't run in `bin/check`.
