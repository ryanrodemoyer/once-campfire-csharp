## Notes for dependents

- **What Thruster does to requests** (thruster@v0.1.23 `internal/`). The app sees these headers,
  as Rails does behind it:
  - `Host` is the client's.
  - `X-Forwarded-For`, `X-Forwarded-Host` and `X-Forwarded-Proto` are set. Without `TLS_DOMAIN`
    (`FORWARD_HEADERS` on), the client's own values are kept and appended to.
  - `X-Request-Start: t=<ms>` is added.
  - `X-Sendfile-Type: X-Sendfile` is added. Rails' `Rack::Sendfile` reacts to it.
  
  The peer is `127.0.0.1`/`::1`, a trusted proxy for `ActionDispatch::RemoteIp`, so
  `request.remote_ip` (sessions' `ip_address`, banned IPs) comes from `X-Forwarded-For` in Rails
  (W02/A01). Benchmarks hit the app port directly and skip all of this.
- **X-Sendfile**: if the app answers with an `X-Sendfile: <path>` header, Thruster serves that
  file itself (`http.ServeFile`: ranges, `Last-Modified`). Rails does this for Active Storage disk
  downloads behind Thruster. Serving the body from the app gives clients the same content, so
  storage tasks may ignore the header.
- **Thruster also**: caches `Cache-Control: public` responses up to 1 MB (64 MB total), gzips
  compressible types of 1 KB or more, and has no request body limit. Its environment is the
  reference's: `HTTP_PORT`, `HTTPS_PORT`, `TARGET_PORT`, `TLS_DOMAIN`, `ACME_DIRECTORY`,
  `EAB_KID`/`EAB_HMAC_KEY`, `STORAGE_PATH`, `CACHE_SIZE`, `HTTP_*_TIMEOUT`, … and their
  `THRUSTER_`-prefixed forms. The app's `ServerSettings.TlsDomain` is informational, since only
  Thruster acts on `TLS_DOMAIN`.
- To run the opt-in proxy tests: `src/Campfire.Server/Front/install-thruster amd64 /tmp/thrust &&
  CAMPFIRE_THRUST=/tmp/thrust dotnet test tests/Campfire.Server.Tests/Campfire.Server.Tests.csproj`.

## Known gaps

- **No native Kestrel front end** (HTTP/2, TLS with ACME reusing Thruster's cache, compression).
  The card makes it optional. Thruster gives parity today, and benchmarks bypass it. If it's
  wanted later, it should be its own task. It has to read Thruster's autocert cache (`<domain>`
  files holding the PEM key and chain, plus `acme_account+key`) and pass the Pebble test above.
- The full multi-stage `docker build` still hasn't run on a networked machine (B01/B04). Nor has
  an arm64 run; arm64 is checked only down to the extracted binary.
- The proxy tests skip in CI, which doesn't install Thruster.
