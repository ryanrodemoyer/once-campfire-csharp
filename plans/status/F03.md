## Notes for dependents

- `bin/setup` is idempotent. It skips the SDK install when `dotnet --version` succeeds in the repo,
  so `global.json` alone decides which SDKs are acceptable. Otherwise it tries Ubuntu's
  `dotnet-sdk-<major.minor>` package (Microsoft's download hosts are blocked in Claude Code cloud
  sessions), then Microsoft's `dotnet-install.sh --jsonfile global.json` into `~/.dotnet`.
- `bin/check` runs plan, restore, format, build and test, always all five, and ends with the list
  of failed steps. Add new checks as another `step` line so CI picks them up.
- CI uses `actions/setup-dotnet` with `global-json-file`, then the same `bin/setup` and `bin/check`
  a contributor runs. It doesn't cache NuGet packages yet.
- The SessionStart hook is synchronous and only runs when `CLAUDE_CODE_REMOTE=true`. It takes
  effect for new sessions once it is on `main`.
