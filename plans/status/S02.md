## What was built (`src/Campfire.Storage/Variants/`)

- `Transformations`: the ordered, symbol-keyed hash after `deep_symbolize_keys`. Values are nil,
  bool, long, UTF-8 string, `RubySymbol`, arrays and nested hashes. It has `reverse_merge`, `as_json`,
  decoding from JSON (keys symbolized, values left as strings), and Ruby 3.4 `inspect`.
- `RubyMarshalWriter`: `Marshal.dump` (4.8) for those values, with symbol links, the `E` encoding
  ivar on strings, and Fixnum/Bignum per marshal.c (a tagged VALUE that fits in 32 bits is a Fixnum).
- `Variation`: `digest`, `key(verifier)`, `Decode(verifier, key, now)` (null when the key
  doesn't verify), `default_to`, `format` (validated against Marcel, `ArgumentError` as in Rails) and
  `content_type`.
- `MarcelExtensions` and `MarcelExtensions.g.cs`: `Magic.by_extension`, `MimeType.for(extension:)`
  and `Magic.new(type).extensions`. `marcel_extensions.rb` generates them from marcel 1.1.0. The
  table is identical to the Rust port's dump from the reference image.
- `Representable`: `variant` / `preview` / `representation` with
  `default_variant_transformations`. A web image keeps its own extension, otherwise `:png`.
  `previewable?` is `video?`, because the reference image has ffmpeg but no poppler or mupdf. It
  raises the Invariable, Unpreviewable and Unrepresentable errors.
- `NamedVariants`: `:thumb`, `:square`, `:large`, `:small` in their Ruby hash order, plus the two
  video previews the app requests.
- `RepresentationUrls`: `url_for(representation)` and `rails_storage_proxy_path(representation)`.
  There is no image work, and each distinct variation's key is signed only once.
- `VariantRecords`: SQL for `active_storage_variant_records`: find, list by blob, the `image`,
  `create_or_find_by!` (insert `ON CONFLICT DO NOTHING`, else the existing row), and delete.
- `VariantProcessor`: `processed` for variants and previews. It reuses any existing record or preview
  image, and otherwise calls S03's delegates outside the writer and records the result.

## Notes for dependents

- **M02** (message rendering): use
  `urls.RedirectPath(Representable.Representation(blob, NamedVariants.MessageThumb))` for images
  and `Representable.Preview(blob, NamedVariants.VideoPoster)` for the video `poster`.
  `RepresentationUrls` is cheap to reuse; make one per `BlobStorage`.
- **S03** supplies `VariantTransformer` (stage the transformed bytes with `variant.Filename` /
  `variant.ContentType`, transformations minus `:format`) and `PreviewImageRenderer` (stage the
  first frame as `<base>.jpg`). Rails passes the variant's content type as declared but still
  identifies it; this belongs with S03's Marcel.
- **S05**: `Variation.Decode` the URL's key, then `Representable.Representation(blob, variation)`.
  A decoded key has string formats, so its digest differs from the app's symbol form. This is the
  reference's `poster-from-key` record, which is a separate record in Rails too. `variation.Format`
  throws `ArgumentException` for an unknown format, as Rails does.
- Avatars and logos (`Users::AvatarsController`, `Accounts::LogosController`) call
  `VariantProcessor.ProcessedAsync(Representable.Variant(blob, NamedVariants.AvatarSquare), ...)`
  when `blob.IsVariable`. They serve the returned blob's file.
- `AttachOne` for a preview image may replace one attached concurrently. Its `ReplacedBlobId`
  purge is ignored here, as `purge_later` belongs to the J lane. Destroying a blob's variant records
  (`before_destroy`) is `VariantRecords.ForBlob` + `Delete` plus purging their images, which is
  the purge job's.

## Known gaps

- Float transformation arguments and integers outside `long` aren't supported. The app uses
  neither; a key that carries one doesn't decode.
- Image and video processing itself: S03.
- Tests live in `tests/Campfire.Storage.Tests/Variants/`, beside S01's `Blobs/`.
