## Acceptance evidence

- [x] All rails_compat crypto vectors pass in both directions (verify Rails output, produce
  Rails-verifiable output).
  - `tests/Campfire.RailsCompat.Tests/Crypto/RailsCompatVectorTests.cs` runs every crypto family
    in `vectors/rails_compat.json` through the primitives:
    - `key_generator` (6): `Key_generator_derives_rails_keys`.
    - `app_verifiers` (8 generate, 15 verify): `MessageVerifier.ForApp(keys, name)`.
      `GenerateRaw` is byte-for-byte Rails' message, and `VerifyRaw` returns the expected JSON
      or refuses (wrong purpose, wrong verifier name, expired, tampered, rotated secret).
    - `signed_cookies` (10 generate, 35 verify): the cookie jar's verifier (`"signed cookie"`,
      HMAC-SHA1, `NullSerializer`, legacy envelope) writes Rails' raw values and reads every
      verify case as Rails does: expiry, wrong name, tampering, a SHA256 digest, pre-5.2 values
      with no metadata, and Marshal values.
    - `encrypted_cookies` (8 generate, 20 verify): Rails' ciphertexts decrypt to Rails'
      plaintext, and our serialized plaintext is the same bytes. Encrypted with Rails' IV, our
      `ciphertext--iv--tag` is Rails' raw value byte for byte, so GCM, the layout and the Base64
      all match. A random-IV message round-trips. Every verify case matches, including tampered
      ciphertext, IV and auth tag, a truncated tag, and the rotated secret. The real session
      cookie from the reference's login flow (`session.session_cookie_raw`) decrypts to its
      session hash.
    - `signed_ids` (14 generate, 31 verify): SHA256, `::JSON` and URL-safe Base64, with a
      fallback to the app defaults through `FallBackTo`. Generation matches, and verify matches
      for the legacy fallback verifier and for standard Base64 of a URL-safe message.
    - `turbo_stream_names` (6 generate, 12 verify): SHA256 with no envelope. A message that has
      purpose metadata is refused when no purpose is given.
    - `sgids.generate` (5): `GlobalID::Verifier` (URL-safe Base64 with padding).
  - **Rails-verifiable output.** Generation is deterministic for the verifier, and our output
    equals the bytes Rails produced for the same input, so Rails verifies it. For the encryptor,
    the fixed-IV comparison shows ciphertext and tag equal Rails'. The random IV is the only
    thing that differs.
  - Mutation check: changing expiry to `now > exp` fails the three "at expiry" vectors.
- [x] Wrong purpose, expired and tampered inputs are rejected.
  - `MessageVerifierTests` checks the reason for each rejection. `Rejects_the_wrong_purpose`
    covers another purpose, no purpose, and a purpose expected where the message has no
    metadata (`PurposeMismatch`). `Rejects_at_and_after_expiry` gives `Expired` at `exp` and
    after it, and the message is valid one tick before. `Rejects_a_tampered_message` flips
    characters in the payload and the digest (`InvalidSignature`). Also covered: malformed
    messages, another secret, and payloads that are authentic but unreadable
    (`InvalidMessage`). Rotations are tried only for format and serialization errors, as in
    `Messages::Rotator`.
  - `MessageEncryptorTests` checks wrong purpose, expiry, a flipped bit in each of ciphertext,
    IV and auth tag, malformed messages, another key, and the 32-byte key requirement.
  - The vector verify cases above reject the same inputs that Rails rejects.
- `bin/check` passes. `Campfire.RailsCompat.Tests` has 250 tests.

## Notes for dependents

Everything is in `Campfire.RailsCompat.Crypto` and uses only the BCL: `Rfc2898DeriveBytes.Pbkdf2`,
`HMACSHA1`/`HMACSHA256`, `AesGcm`, `CryptographicOperations.FixedTimeEquals`, and
`System.Text.Json.Nodes`.

- **Keys.** `new KeyGenerator(secretKeyBase)`, then `.GenerateKey(salt, length = 64)`. It uses
  PBKDF2-HMAC-SHA256 with 1000 iterations and caches keys. Each call returns a copy. Build one
  at boot and share it.
- **Verifiers.** `new MessageVerifier(secret, MessageDigest, MessageEncoding, MessageSerializer)`
  takes every option, because each Rails use configures it differently. `RailsSecrets` in the
  tests shows the reference's configurations for signed cookies, encrypted cookies, signed ids,
  Turbo stream names and SGIDs. C02 and C04 can copy them. `MessageVerifier.ForApp(keys, name)`
  is `Rails.application.message_verifier(name)`; Active Storage uses `"ActiveStorage"`.
  `.FallBackTo(other)` adds a rotation.
- **Values.** Values are `JsonNode?`, and JSON `null` is a C# `null`. `Generate`/`Verify` take
  and return nodes. `GenerateRaw(dumped)`/`VerifyRaw` take and return what the serializer
  dumps, so callers control key order and escaping. For `MessageSerializer.Null` (the cookie
  jars), the dumped form is the string itself: sign `RailsJson.Encode(value)` with
  `GenerateRaw`, and parse what `VerifyRaw` returns.
- **Results.** `MessageResult<T>` has `Value` and `Error` (`MessageError.None`,
  `InvalidSignature`, `InvalidMessage`, `Expired`, `PurposeMismatch`). The cookie jars retry
  with no purpose on any error. Signed ids rely on `FallBackTo`.
- **Encryptor.** `new MessageEncryptor(key32, MessageSerializer.Null)`. Use `EncryptAndSign` or
  `EncryptAndSignRaw` to write, `DecryptAndVerify` to read, and `Decrypt` for the bytes before
  envelope handling.
- **Serializers.** `Null` is `NullSerializer` with the legacy envelope. `Json` is `::JSON`.
  `JsonWithFallback` is `:json`, which refuses Marshal. `JsonAllowMarshal` is
  `:json_allow_marshal`, which reads a marshaled String (Rails 7.0 SGIDs, signed ids). Cookie
  values are `JsonWithFallback`.
- **JSON.** `RailsJson.Generate` is `JSON.generate` (json 2.21.2 escapes and float layout).
  `RailsJson.Encode` is `ActiveSupport::JSON.encode`: it adds `<`, `>` and `&`,
  and leaves U+2028/9 unescaped. `RailsJson.TryParse` keeps key order, applies Ruby's rule for
  repeated keys, and keeps integers at any size.
- **Also public:** `RubyBase64` (strict and lenient URL-safe decoding as in Ruby),
  `SecurityUtils.SecureCompare`, and `MessageMetadata.Iso8601Millis` (`Time#iso8601(3)`, truncated).
- **Shared file touched:** `tests/Campfire.RailsCompat.Tests/Campfire.RailsCompat.Tests.csproj`
  now references `Campfire.Vectors`, as V03's notes describe.

## Known gaps

- The jar semantics themselves are C02's: purpose fallback, `cookies.permanent`, and Rack
  escaping. The signed-id purpose naming, the SGID locate rules (including self-validated
  globalid < 1.0 metadata) and Turbo's helpers are C04's. Their vectors run here only through
  the primitives.
- A Ruby run of Rails verifying our output (as `reference-tools/rails_compat_verify_rust.rb`
  does for Rust) isn't wired up. Byte-equality with Rails' own output stands in for it. V01
  can point that script at C# output once the higher layers exist.
