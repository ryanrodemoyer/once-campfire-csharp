## Notes for dependents

- Namespace `Campfire.Jobs.RestrictedHttp`.
- `PrivateNetworkGuard.ResolveAsync(host)` returns the first public `IPAddress`. It throws
  `PrivateNetworkViolationException` (`RestrictedHTTP::Violation`) when the host is private or
  malformed, and `UnresolvableHostException` (`Surfguard::Unresolvable`) when it resolves to
  nothing. `PrivateNetworkGuard.IsPrivateIp` is `private_ip?`. `PrivateNetworkGuard.System` uses
  the system resolver. Tests pass their own `IResolver`.
- `RestrictedHttpHandlers.OpenGraph(guard)` and `.WebPush(guard)` are `SocketsHttpHandler`s
  whose `ConnectCallback` dials only an address the guard admits. That is
  `request.Options[RestrictedHttpHandlers.PinnedAddress]` when it is set (`Net::HTTP#ipaddr=`),
  otherwise the guard's answer for the host. Either way the address is checked again before the
  connect. Both handlers skip proxies, never reuse a connection (Rails opens a fresh `Net::HTTP`
  per pinned request), don't follow redirects, and inflate gzip and deflate. WebPush refuses
  anything except https on port 443. The optional `Dialer` argument exists for tests.
- I03: resolve once, pin it, and pin each redirect hop again (`Opengraph::Fetch#resolve_redirect`).
  Rails' 60s open timeout is set as `ConnectTimeout`. Read timeouts and the 5MB cap belong to the
  caller.
- I02: `Push::Subscription#resolved_endpoint_ip` maps to `ResolveAsync`, catching both exceptions
  and returning null.
- `RestrictedHttpHandlers.Webhook()` is unrestricted by design. It honours the environment proxy
  like `Net::HTTP.new` and has a 7s connect timeout.

## Known gaps

- The tests live in `tests/Campfire.Jobs.Tests/RestrictedHttp/`, the test project for
  `Campfire.Jobs`, which is outside this card's `owns`.
- These differences from Rails need entries under README "Known differences", which this task
  doesn't own:
  1. The guarded handlers ignore `http_proxy`. `Opengraph::Fetch` uses `Net::HTTP.start`, which
     would use it and so lose the pinned address.
  2. Answer order within one address family comes from `getaddrinfo`, not Ruby's `Resolv`. That
     only changes which public address gets pinned when a host has several.
- `Vectors/generate.rb` ran on Ruby 3.3 with the ipaddr 1.2.7 gem, the version Ruby 3.4 bundles,
  rather than inside the reference image.
