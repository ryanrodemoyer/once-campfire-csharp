## Notes for dependents

- **Ruby/** (`Campfire.RailsCompat.Ruby`): `RubyString.ToI/ToIChecked/Strip`,
  `ActiveModelInteger.Cast` (what `find(params[:id])` binds; null where Rails raises),
  `RubyFloat.ToF/ToS`, `RubyEscape.HtmlEscape/AppendHtmlEscaped/CgiEscape/UrlEncode/RackEscape`,
  `RackByteRanges.Parse` (null: serve everything; empty: 416), `RubyTime.Parse/UtcOffset`
  (`Time.new(string)`), `RubyCase.Capitalize/Downcase`.
- **Formatting/** (`Campfire.RailsCompat.Formatting`): `ActiveRecordTime.ToDb/FromDb/TruncateToMicroseconds`
  for datetime columns (D02 should use these; D01's private `SchemaPreparer.QuotedDate` is the same
  as `ToDb`), `TimeFormats.ToFsNumber/ToFsDb/ToFsUsec/ToFsEpoch/ToF/Iso8601/AsJson`,
  `TextHelpers.Truncate/ToSentence`, `StringExtensions.AllEmoji`. Times are `DateTimeOffset`,
  printed in UTC (the app sets no `config.time_zone`).
- **`to_fs(:epoch)` is not the nearest double.** Ruby's `Time#to_f` is `(double)nanoseconds / 1e9`
  (`rb_time_unmagnify_to_float`), so 2028-05-20 09:54:34.005 gives 1842429274004. 6 of the 513
  vector times differ from the "nearest double" computation the Rust port uses.
- **`truncate` returns plain text.** The view helper escapes it; escape on output.
- **.NET's shortest double formatting is wrong at two powers of two** (`2^-25`, `2^-958` don't read
  back); `RubyFloat.ToS` detects that and finds the correct form from the exact value.
- **Not ported because the app doesn't use them** (grep of `reference/app`, `lib`, `config`):
  `pluralize`, `parameterize`, `number_to_*`/`number_with_*`, `time_ago_in_words`, `humanize` and the
  inflector. `Duration#ago` (`CONNECTION_TTL.ago`) is `DateTimeOffset` arithmetic.
- **Shared file touched**: `tests/Campfire.RailsCompat.Tests/Campfire.RailsCompat.Tests.csproj`
  (F02's, done) now references `Campfire.Vectors` and `Microsoft.Data.Sqlite`, as the V03 notes
  ask; other RailsCompat tasks' tests share it.

## Known gaps

- `ActiveRecordTime.FromDb` reads what `Time.new(text, in: "UTC")` reads. Where that raises,
  Rails falls back to `Date._parse` (`fallback_string_to_time`), which isn't ported; the 22
  spellings in the vectors that only the fallback reads (`"2026-01-01 12:00"`, a trailing space,
  `EST`, a lowercase `t`...) give null here, pinned by `OnlyFallbackSpellingsDiffer`. Neither
  Rails nor SQLite writes any of them to a datetime column. Years outside 1 to 9999 are null too.
- `formatting.json` was generated with Ruby 3.3.6 (Unicode 15.0.0, the same as 3.4.10), since the
  session could not download Ruby 3.4.10 or run the reference image. Active Support, Active Model
  and Active Record are the pinned revision. `RubyTime` follows Ruby **3.4.10**'s `time.c`
  (`time_init_parse`, `utc_offset_arg`, `validate_vtm`, `rb_time_unmagnify_to_float`), read from
  the `v3_4_10` tag. V01 can regenerate the file in the reference image.
