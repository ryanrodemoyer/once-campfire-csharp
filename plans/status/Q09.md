## Root cause analysis

### 1. Typing notifications tests — ordering race

**Test files**: `tests/Campfire.Cable.Tests/Channels/ChannelBehaviorTests.cs`

**Root cause**: The two typing tests (`Typing_notifications_broadcast_start_and_stop_to_the_room` and `Typing_notifications_reach_the_room_however_the_channel_is_spelled`) asserted message delivery order between two WebSocket clients with sequential `NextAsync` calls:

```csharp
// Before: sequential — assumes reader receives before typist
Assert.Equal(expected, await reader.NextAsync());
Assert.Equal(expected, await typist.NextAsync());
```

When `typist.PerformAsync` triggers a broadcast via `TypingNotificationsChannel.Broadcast` → `PubSubHub.Broadcast`, the two connections' `WriteLoop` tasks deliver the frame over their respective WebSockets concurrently. The order is non-deterministic: it depends on thread scheduling of the two independent write loops. If the message arrived at `typist`'s WebSocket before `reader`'s, `reader.NextAsync()` blocked indefinitely (10s timeout → `OperationCanceledException`).

**Fix**: Start both `NextAsync` calls concurrently before awaiting either, so both are waiting when the broadcast arrives:

```csharp
// After: concurrent — both reads start before the broadcast arrives
var readerNext = reader.NextAsync();
var typistNext = typist.NextAsync();
Assert.Equal(expected, await readerNext);
Assert.Equal(expected, await typistNext);
```

### 2. OpenGraph vector test "invalid image url /image.png" — disposal race

**Test file**: `tests/Campfire.Jobs.Tests/OpenGraph/ScriptedServer.cs`

**Root cause**: The `AcceptAsync` method's catch block only handled `OperationCanceledException` and `SocketException`. During `DisposeAsync`, `listener.Stop()` sometimes executes before `AcceptTcpClientAsync` checks the cancellation token, causing `TcpListener.AcceptTcpClientAsync` to throw `System.InvalidOperationException: "Not listening. You must call the Start() method before calling this method."`. This exception was uncaught, causing `await accepting` in `DisposeAsync` to propagate the exception and fail the test with:

```
System.InvalidOperationException : Not listening. You must call the Start() method before calling this method.
   at System.Net.Sockets.TcpListener.AcceptSocketAsync(CancellationToken cancellationToken)
   at System.Net.Sockets.TcpListener.AcceptTcpClientAsync(CancellationToken cancellationToken)
   at Campfire.Jobs.Tests.OpenGraph.ScriptedServer.AcceptAsync() in .../ScriptedServer.cs:line 57
   at Campfire.Jobs.Tests.OpenGraph.ScriptedServer.DisposeAsync() in .../ScriptedServer.cs:line 185
```

The race: `DisposeAsync` calls `stopping.CancelAsync()` first, then `listener.Stop()`. If `AcceptTcpClientAsync` is in the accept phase when `Stop()` is called (before the cancellation token is observed), it throws `InvalidOperationException` instead of `OperationCanceledException`.

**Fix**: Added `InvalidOperationException` to the `AcceptAsync` catch filter:

```csharp
// Before
catch (Exception e) when (e is OperationCanceledException or SocketException)

// After
catch (Exception e) when (e is OperationCanceledException or SocketException or InvalidOperationException)
```
