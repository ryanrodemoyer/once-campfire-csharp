## What was built

  pagination at `AccountsController.UsersPerPage`, the turbo-stream render, and
  `GearedPagination::Headers` for JSON formats), `update` (`role_params`) and `destroy`

  `destroy` (`UserLifecycle.Unban`), redirecting to the person's page.
- `Controllers/Accounts/UsersRoutes.cs`, `Controllers/Users/BansRoutes.cs`: route bindings;
  `accounts/users#new/create/show/edit` raise ActionNotFound (404).
- `Views/accounts/users/index.turbo_stream.erb.cs` (declared in `Views/accounts/users/index.cs`),
  rendering A03's `_user` and `_next_page_container` partials.

## Notes for dependents

- `ActiveRecord::RecordInvalid` is 422 in Rails' `rescue_responses`, but W01's
  `HttpErrors.StatusFor` maps `Campfire.Data.Lifecycle.RecordInvalidException` to 500. The bans
  controller wraps it in a 422 exception of its own; mapping it in `HttpErrors` would fix it for
  every controller.
- Geared pagination's `Link`/`X-Total-Count` only ever appear when the request's first format is
  JSON and it still accepts the turbo stream: a plain JSON request has no template and is a 406
  before the after_action runs.
