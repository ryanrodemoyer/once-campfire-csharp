## Notes for dependents

- **AuthenticityToken** (`Campfire.RailsCompat.Csrf`):
  - `GenerateSessionToken()` is Rails' `SecureRandom.urlsafe_base64(32)`. Store it on `Session.CsrfToken` (`_csrf_token`).
  - `FormToken(sessionToken, action, method, requestPath)` is `form_authenticity_token`. Null action or method is the meta-tag token (masked global). Per-form tokens are on, matching `load_defaults 8.2`.
  - `IsValid(sessionToken, encoded, requestPath, requestMethod)` is `valid_authenticity_token?`. `requestMethod` is `request.request_method` after `Rack::MethodOverride`.
  - Parameter name `authenticity_token`, header `X-CSRF-Token`. Either one is enough.
- **ForgeryProtection.Verify(ForgeryRequest)**:
  - GET and HEAD pass and do not read the token. GET sets `MarkedForSameOriginVerification`.
  - Otherwise the origin check runs, then the param and the header. Failure status is 422 (`:unprocessable_content`).
  - `ForgeryRequest.Exempt` is the bot-key hook (`authenticated_by.bot_key?`) and `skip_forgery_protection` (PwaController). The before-action does not run.
  - `AllowForgeryProtection = false` is the Rails test-environment switch. Campfire keeps it on.
  - `GeneratedSessionToken` is set when the check had to mint one. Store it even if verification then fails; Rails commits it via `commit_csrf_token`.
  - `ThrowIfRejected()` is `protect_from_forgery with: :exception`.
  - `VerifySameOriginRequest` is the after-action that rejects a non-XHR JavaScript response on a marked GET.
- The pinned Rails (rails@1a02651) does not consult `Sec-Fetch-Site`. The reference's own session posts send no such header and still return 302. A later Rails `protect_from_forgery using: :header_only` is not this app.
