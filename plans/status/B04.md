### Recommended configuration for B05 (final benchmark)

**ReadyToRun (`PublishReadyToRun=true`) + Server GC (default).**

Rationale:

1. **Compilation mode**: JIT and ReadyToRun are within 0.8% of each other on throughput (well
   within measurement noise — the throughput scores differ by 16,883 vs 16,752). ReadyToRun has
   a clear memory advantage: idle memory 43 MB vs 60 MB (−28%), idle anon 31 MB vs 46 MB (−33%),
   and peak memory 216 MB vs 230 MB (−6%). Cold start is identical (~202 ms). R2R produces
   pre-compiled IL that starts at native speed without the JIT warm-up cost.

2. **GC mode**: Server GC provides 5–6% higher throughput than Workstation GC across all
   workloads (e.g. 3,161 vs 2,842 req/s for sidebar). Workstation GC uses less peak memory
   (170 MB vs 216 MB for R2R) but the 170 MB peak is already low; dropping 5–6% of throughput
   for 46 MB of peak memory is not warranted on production hardware. p99 latency is also lower
   with Server GC (e.g. room_show 96 ms vs 105 ms for R2R at c=16).

3. **Native AOT**: Could not be built. The `Campfire.Templates.Generator` project targets
   `netstandard2.0` (required by Roslyn for source generators), which the .NET 10 SDK rejects
   under `PublishAot=true`. The generator is an analyzer-only dependency
   (`ReferenceOutputAssembly=false`, `OutputItemType=Analyzer`). To enable AOT, the generator
   needs `<IsAotCompatible>false</IsAotCompatible>` in its `.csproj` — a one-line change that
   should be made in F02 or P01. See the issue filed on #70 for follow-up.

### Build infrastructure

The ReadyToRun variant Dockerfile lives at `bench/runtimes/Dockerfile.r2r`. It is identical to
the main `Dockerfile` except for `-p:PublishReadyToRun=true` on the `dotnet publish` line.
Build with:

```sh
docker build -t campfire-csharp:r2r -f bench/runtimes/Dockerfile.r2r .
```

The Native AOT attempt is at `bench/runtimes/Dockerfile.aot` (non-functional — see above).

The runner script at `bench/runtimes/run-matrix.sh` runs all four configurations sequentially
against the B02 oracle, and `bench/runtimes/analyze.py` produces the comparison tables.
