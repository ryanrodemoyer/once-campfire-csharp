- [x] Stored -> display -> edit -> save -> display -> plain text -> search index cycle matches the reference
  - **Plain text.** `plain_text` in `vectors/richtext/expected.json` is `message.body.to_plain_text`
    as the reference converted all 658 bodies (641 convert, 17 raise).
    `PlainTextVectorTests.Converts_each_body_as_the_reference_does` (658 rows) matches every

  - **Edit.** `editable` is the `<lexxy-editor>` value, `render_custom_attachments_in(editable_body(message))`

    `EditableVectorTests.Builds_each_editor_value_as_the_reference_does` (658 rows) matches every
    one, including the JSON-encoded partials (`<` escaping) and the Trix-era mentions and
    embeds rebuilt as Lexxy's. The four cases of `reference/test/helpers/rich_text_helper_test.rb`
    are ported alongside.
  - **Display** of the stored body is R03's `PresentationVectorTests` (658 rows).
  - **Save, display, plain text.** `EditRoundTripTests.Saving_an_untouched_edit_shows_and_indexes_what_the_reference_did`
    takes every case whose editor value builds and whose plain text converts (546; 545 rows plus

    stores it, then displayed and converted. Display and plain text equal the reference's for the

    and finds it by its words and mentioned names but not by markup (`span`, `sgid`, `lexxy`);
    `reference/test/models/message/searchable_test.rb`'s rich text case is ported.
  - Action Text's own `plain_text_conversion_test.rb` (all 21 cases, at the pinned Rails revision)

- [x] Webhook plain body with recipient mentions removed matches

## Notes for dependents

- `Campfire.RichText.PlainText.RichTextPlainText`
  - `PlainTextBody(body, attachmentFilename, context)` is `Message#plain_text_body`: what D04/M05
    pass as `plainTextBody` to `MessageLifecycle` (search index), and what push notifications, the
    message JSON, `/play` and emoji detection read.
  - `ToPlainText(body, context)` is `RichText#to_plain_text` (null body gives `""`).
  - `WithoutRecipientMentions(plainTextBody, botName)` is the webhook payload's `body.plain`.
  - All of them throw where Rails raises (`RichTextRaisedException`, `HtmlParseException`,
    `RubyUriException`); Rails lets those propagate (a 500, or a failed job).
- `Campfire.RichText.Editing.EditableContent`
  - `EditorValue(storedBody, context)` is the `value` of `messages/edit.html.erb`'s editor, or
    null for no `value` attribute; the view HTML-escapes it. It raises for any attachment that
    isn't a mention or opengraph embed, as Rails' edit page does (the Rust port drops missing
    attachables instead; we don't).
  - `StoredBody(postedBody)` is `ActionText::Content.dump`: how an assigned body is stored.
- `RichTextPlainText.AttachmentNodes` finds `action-text-attachment` by local name in any
  namespace, as Nokogiri's CSS does for HTML5 documents (an attachment inside `<svg>` is
  converted; the `attachment in svg` vector proves it). R03's `AttachmentResolution.AttachmentNodes`
  matches HTML-namespace elements only; display still matches all its vectors, but a follow-up
  could share one selector.
- `ContentFilters.ToPlainText` (R02, used by `remove_solo_unfurled_link_text`) is a separate,
  looser conversion; `PlainTextConversion.NodeToPlainText` is the faithful one if it is revisited.
