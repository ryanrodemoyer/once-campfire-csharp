## How the C# server was run

`campfire server` on main never builds a `WebApp`: `ServerCommand.Pipeline` calls
`Router.HandleAsync` directly, so controllers can't find `WebApp.Of(context)` (VS01's status and
#26 recorded this). To get numbers, the C# image was built with
`bench/results/first-20261009/server-composition.patch`, which builds a `WebApp` with the real
database, keys, assets and blob storage but **no-op** broadcaster, job queue and connection revoker.
The patch is kept with the results for reproducibility and is not merged: P05 (#173) owns the
server composition and wires the real cable server, job runner and revoker.

## Notes for dependents

- The four GET workloads (room, messages, sidebar, search) do no broadcast or job work, so their
  numbers stand.
- **Post a message is not valid.** Rails renders and broadcasts the new message over Action Cable
  and enqueues jobs on every post; with no-op seams C# skips that work. B03 re-measures posting
  once P05 lands.
- The room and messages pages are close to Rails (1.1× and 0.8×) while sidebar and search are 8×
  and 1.9×, so message rendering is the first thing for B03 to profile.
- `bench/bin/report bench/results/first-20261009` reprints the tables.
