## What changed

- **`src/Campfire.Server/Cli/ServerCommand.cs`**: Fixed the production server pipeline to
  build a `WebApp` (Database, Keys, Router, Assets, BlobStorage, DomainSeams with no-ops) and
  serve through `WebApp.HandleAsync` instead of calling `Router.HandleAsync` directly. This
  was the known gap recorded in VS01's status (#66): "`campfire server` does not serve this
  slice yet. `ServerCommand.Pipeline` calls `Router.HandleAsync` directly and never builds a
  `WebApp`." Controllers require `WebApp.Of(context)`, which the previous pipeline never
  installed as a context feature.

## Notes for dependents

- B03 and B04 depend on these results. The numbers are in `bench/results/first-20261009/`.
  `bench/bin/report bench/results/first-20261009` reprints the tables.
- The server now boots with a full `WebApp` wired: SQLite database, key generator for
  cookies/signed IDs, asset bundle, blob storage over the files directory, and no-op domain
  seams (broadcaster, job queue, connection revoker). The Action Cable server, job runner and
  Thruster are not yet mounted; those are P03, RT02/RT03 and I01's work.
- The no-op seams mean broadcasts, jobs and connection revocations are silently dropped. The
  five measured workloads don't need them: each HTTP request does its own database work and
  renders a response in-process.

## Known gaps

- The `WebApp` seams (broadcaster, job queue, connection revoker) are no-ops. The real
  implementations in RT01 (CableServer as IBroadcaster), I01 (JobRunner as IJobQueue) and
  RT01/RT04 (CableConnectionRevoker) are not wired to the server yet. RT02's end-to-end test
  already flags this on P01's issue #26.
- `src/Campfire.Server/Cli/ServerCommand.cs` is owned by P01. This task edited it because
  the server was non-functional without a `WebApp`, and VS01 already raised the issue on #26
  with the same request. The fix is minimal: build a `WebApp` with the pieces already
  available in `Build` and call `WebApp.HandleAsync`.
