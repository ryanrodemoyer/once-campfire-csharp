  - Load: 16 CPU-burning `sh` loops, one per core (load average 12.6 on start, all cores busy).
  - Loop script ran `dotnet test --no-build -c Release` for `ScansPathologicalPagesInLinearWork` (Campfire.Jobs.Tests) and `A_signed_stream_name_confirms_and_delivers` (Campfire.Cable.Tests), 50 iterations each.
  - Result: 50/50 runs of each test reported `Passed: 1, Failed: 0`; total failures 0. Logs were kept in `/tmp/opencode/Q14-{jobs,cable}.N.log` (not committed).
- [x] `bin/check` green on this branch (format, build, all test projects, `plan validate`): `bin/check passed`.
- [x] The OpenGraph test no longer has a wall-clock threshold. `ScansPathologicalPagesInLinearWork` compares the bytes `GC.GetAllocatedBytesForCurrentThread` counts for a full-size page and a half-size page, and asserts full < 3 × half. Linear scanning gives about 2×; quadratic would give about 4×. Measured on the first page: 184,107,616 bytes full and 92,065,976 half, a ratio of 2.00.
- [x] The Cable test waits on the event, not a delay. The likely cause, not reproduced locally, is an ordering race in `src/Campfire.Cable/Server/CableConnection.cs`: the confirmation frame was queued before the stream was subscribed in the hub, so a broadcast sent as soon as the client saw the confirmation could be lost, and the client then waited out its 10 s patience. Rails sends the confirmation only after `pubsub#subscribe` succeeds (`actioncable/lib/action_cable/channel/streams.rb`, `stream_from`: "Don't send the confirmation until pubsub#subscribe is successful"). The fix subscribes the streams before delivering the confirmation, in the same order as Rails. The test itself needed no change.

## Notes for dependents

- The OpenGraph check counts allocations rather than steps, so it needs no change to production code. It catches regressions that allocate in proportion to work squared (for example, copying the remaining input per token). It does not catch a quadratic loop that scans without allocating. Adding an explicit step counter to `LegacyHtml.Scanner` would close that gap, but it would put test-only instrumentation in production code, so it's left for a follow-up if wanted.
- `CableConnection` now starts streams before queueing the confirmation. Rejected subscriptions are unchanged.

## Known gaps

- The allocation-based linearity check, described above, does not see non-allocating quadratic work.
